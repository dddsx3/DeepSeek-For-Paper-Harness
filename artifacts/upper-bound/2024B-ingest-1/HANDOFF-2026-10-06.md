## §4 踩过的坑（每条都有真实代价；接手前必读）

### 4.1 门禁假阳性：比漏报贵得多（本节 7 条全部真实发生）

假阳性的代价不是"多拦一次"，而是三连：**整阶段白跑（约 1 小时）→ 回灌的 finding 诱导模型
把对的改错 → 真缺陷被遮住**。本轮 7 次误报：

1. **`METHOD_CLAIMS_MACHINE` 只认参考形态**（`<!-- METHOD_CLAIMS_MACHINE`）——模型用的是
   本仓库家规 `<!-- BEGIN X -->…<!-- END X -->`，8 条签名一直在，门禁读不到（假阴性）。
   还有个二阶坑：用"懒匹配到最近 `-->`"去兼容家规也不行——匹配到的是 BEGIN 自己的结束符，
   块体为空。**必须**显式找 BEGIN，再找 END。
2. **海象运算符**：`if X := bool(…)` 被判"未定义的常量名"。`definitionsIn` 补了海象/
   元组解包/括号式导入（含 `as`）/`global`。
3. **括号式多行解包**：`(A,\n B,\n) = X`——最后一个名字后面是"换行+逗号+`) = `"，
   单行正则抓不到 → **三次阶段尝试浪费在同一处**。
4. **`import X as Y` 绑定的是 Y**：`import params as PARAMETERS` 后 `getattr(PARAMETERS,…)`
   被判"未定义"。且引用扫描要**先清 import 行**（`from p import DEFAULTS as P` 里的
   `DEFAULTS` 是来源名不是引用）。
5. **`result_constraints` 只认裸字符串**：模型写成 `{"id":…, "expression":"lambda …"}`
   （信息更全）被判"既不是 lambda 也不含比较符"。
6. **合规自审字典**：`{"normal_approximation_as_primary": False}` 是"声明没用"，
   被读成"出现降级签名"→ 硬失败。**必然死循环**且回灌会诱导模型删掉诚实登记。
7. **traceback 绝对路径**：`File "D:\…\params.py"` 里的反斜杠让 `[^"\\]` 整帧失配 →
   定向修复静默失效（第一次真跑时一轮都没执行）。

**教训**：前 6 条全部是"判形式不判实质"。凡是"模型换个写法就不认"的判据，都要按这条重审；
**验证样例必须包含真实输入的完整形态**（Windows 绝对路径、多行结构、别名、包装标记）——
我自己写测试用的干净样例没一次拦住过真实失败。

### 4.2 中转（opencode zen / space-bunny-free）的四个行为

1. **流包装泄漏**：回答末尾拖 `]<]minimax[>[</content>`（上游路由标签+包装闭合）。
   模型与契约都管不了 → 确定性剥离（`salvageTrailingJunk`：≤3 行、剥完能 `ast.parse` 才收）+
   验证-重问循环。
2. **整段缓冲**：有时把整个回答缓冲到结束再发（一片生成 5-8 分钟零字节）→ 180s 空闲看门狗
   会**误杀正在正常生成的请求**。已放宽到 600s。
3. **截断**：单片 33-88KB 必截断，且 `finish_reason` 有时缺失（截断不可检测）→
   落进文件就是语法残骸。防线：紧凑契约 + 分片 ast.parse + 语法重问。
4. **无预兆抖动**：`EMPTY_STREAM` / `fetch failed` 连续 streak / `finish_reason missing`。
   传输层重试（8 次/5s 阶梯）+ 压缩重问 + 空闲看门狗都已接；遇到连续 `fetch failed`
   15 分钟以上，直接重启循环。

### 4.3 运维坑

1. **并发循环毁掉一切**：曾有三个循环同时往同一个 stages/ 写——门禁报告与磁盘文件
   对不上的根因。**接手时先数进程**（§6.3），确认只有一个循环。
2. **nohup 会被工具会话回收带走**（静默死，无失败信息）。必须用 `Start-Process`
   脱离启动（§6.1）。即便如此也可能在数小时后死（原因不明，疑似机器休眠）——
   **以日志 mtime 判断活性**，超 30 分钟没动就重启。
3. **`--stage-next` 每次是独立进程**：改了源码不用重启循环，下一轮自动生效；
   但**正在跑的那一轮**用的还是旧代码。
4. **门禁报告可能是过期的**：`_gate-report.json` 只在门禁真的跑过时更新。读它之前先看 mtime。
5. **vitest 5 秒默认超时在满负荷 + 流水线并行时假红**（失败集合每次不同、孤立跑稳定通过）。
   已给 4 条端到端用例补显式超时；再遇到先孤立跑一遍再定性。

### 4.4 架构/契约坑

1. **契约承诺了检查就要真的有检查**：简报点名 3 条门禁而 `GATES` 里不存在，是最坏的一类
   不一致（模型按"会被核"的假设写，实际无人核）。已有防漂移测试（简报点名的门禁必须登记）。
2. **契约要求文件就要给分片槽位**：`params.py`、`data_check.py` 都踩过——契约要求它、
   计划里没它的位置，模型永远交不出来。
3. **契约要求运行时能力就要布好环境**：让 `data_check.py` 读 `PROBLEM_FACTS.json`，
   却没把文件布进 cwd → `FileNotFoundError`。现在 `stageCodeInputs()` 在冒烟与阶段 4
   之前拷。
4. **模型不知道运行环境长什么样**：它按上游消费路径拼出 `03-code/01-prob-analysis/…`。
   环境形态必须写进契约（已写）。
5. **"探针不是交付"与"失败证据要留"的交汇**：冒烟运行新产生的文件要删（门禁卫生），
   但**失败时先读出报告内容再删**（`data_check.json` 是"为什么失败"的直接证据）。

```bash
powershell -NoProfile -Command "Get-CimInstance Win32_Process | Where-Object { ($_.Name -eq 'node.exe' -and $_.CommandLine -like '*paper-shell*') -or ($_.Name -eq 'bash.exe' -and $_.CommandLine -like '*run-loop-detached*' -and $_.CommandLine -notlike '*CimInstance*') } | ForEach-Object { try { Stop-Process -Id $_.ProcessId -Force -ErrorAction Stop } catch {} }"
sleep 4
powershell -NoProfile -Command "Start-Process -FilePath 'D:\deepseek modex\deepseek-harness\artifacts\upper-bound\2024B-ingest-1\launch-loop.cmd' -WindowStyle Hidden"
```
（第一条先杀残留——**必须先杀再启**，两个循环并发会互相覆盖产物。）
