# 编程实现与真跑结果说明

## 执行方式与产物边界

在 `code/` 工作目录执行 `python main.py`。编排入口同步、依次调用问题一至问题四的求解模块，等待全部求解结束并将量统一写入工作目录下的 `outputs.json`。各问脚本也直接定义可复算函数，便于独立回归。任何必需结果缺失、非有限、违反登记容差或未通过阻断式核验时，程序均以非零状态退出，不以打印文本代替落盘结果。

本说明不手填任何求解数值。所有关键数值、扫描序列、候选策略、核验误差和通过标志均以 `outputs.json` 中由本次执行生成的字段为准；具体取数路径由 `DELIVERABLES.json` 的 `ledger_keys` 逐字公布。问题四全部结果保留 `scenario_only` 标识，不解释为企业真实批次观测。

## 问题一：精确二项检验与有限序贯对照

问题一使用精确二项尾概率和整数阈值枚举，不使用正态近似。拒收情形同时核验标称率处第一类错误约束与登记备择率处功效约束；接收情形直接枚举整数临界次品数并按登记规则处理并列。对每个备择幅度和第二类错误上限组合均重新搜索样本量，同时输出完整灵敏度表、接收特性曲线数据及单调性探针结果。

固定方案的主要结果位于 `problem1.case95` 与 `problem1.case90`。有限序贯方案采用对数似然比随机游走和有限截断，分别计算两种率下的期望检测数、实际错误概率和选择标志。程序只允许在精确约束、截断资源及期望检测数比较全部通过后选择序贯方案；否则固定方案获胜。无上限序贯方案不参与实现。

## 问题二：两零件闭环决策

问题二参数适配器统一接受当前参数模块中的扁平成本字段，并显式映射零配件购买单价、零配件检测成本、成品装配成本、成品检测成本、市场售价、调换损失和拆解费用。六个表一情形及全部登记策略均走同一适配和求解路径，回归检查同时保存每个情形的输入快照、策略、利润和通过标志。

状态模型包含缺件、合格件、次品及明确的吸收交付状态。每次装配尝试最终以报废、拆解回流或合格交付结束，转移矩阵在求解前检查可达闭合类和谱半径。价值递推与独立事件账本分别计算单位最终合格交付利润；账本逐项记录采购、零件检测、装配、成品检测、拆解、调换损失和市场收入。检测出的次品采购款不返还，回收件免采购仅通过状态转移体现，调换损失不替代补发品的生产成本。

策略表为全部登记决策组合的完整结果，而非只保留获胜项。灵敏度输出包含缺陷率、检测成本、拆解费用和调换损失扫描对应的最优策略及利润序列；盈亏平衡数据为二维参数网格上的策略标签和利润差。主要结果位于 `problem2.cases`，完整策略对照和核验字段位于 `problem2.strategy_table` 与 `problem2.validation`。

## 问题三：装配网络情景、退化对照与单位修复

装配引擎以显式父节点边表建立有限有向无环图，不把父节点层数写死为单一固定层数；启动时校验节点标识、父节点引用、孤立节点和环路。求解结果记录每次节点投入的合格产出率 `Q_v`、每次投入现金成本率 `C_v`、单位合格成本 `U_v=C_v/Q_v` 及零产出策略的剔除标志。父节点转移只使用同一事件轨迹的投入成本率与产出率，不把 `U_v` 再次乘以 `Q_v`。

图一原件及其可校验父节点边表未随上游产物提供，因此表二分组推断拓扑和输入数不同的替代拓扑均明确标记为条件情景，不宣称为正式图一答案。两个情景分别执行全节点失败处置、拆解回流、市场退回和补发流程；根节点无论是否检测，失败处置分支都进入同一事件账本。主要结果位于 `problem3.primary` 与 `problem3.alternative`，拓扑利润差、图结构状态和可达状态规模另存于相应验证字段。

两零件退化网络作为阻断式验收实例，对问题二的全部登记策略逐项比较利润及成本分项。最大绝对差保存为 `problem3.validation.degeneration_max_error`；超过现金流容差时终止。缩小退化实例另设独立穷举参考解，用以核验动态规划结果，而不把该有限核验冒充完整装配树的全策略穷举证明。

## 问题四：情景抽样、精确区间与稳健重解

由于没有各参数节点的真实样本量和观测次品数，程序从登记情景次品率生成二项样本，并保存每个节点的 `n_v`、`x_v` 和点估计。点估计只由生成计数计算，情景中心率不被直接冒充为估计值。样本量依据各参数自己的区间精度目标独立搜索，不复用问题一的最小检验次数；输出还包含登记样本量网格上的区间宽度、策略一致率和利润范围序列。

Clopper–Pearson 区间显式分支处理零次品、全次品和内部计数。程序保存边际错误率、端点次序、内部 Beta 分位数结果及二项反演交叉核验。问题二和问题三分别按各自参数节点数分配 Bonferroni 边际错误率；输出名称明确为联合置信域及稳健利润包络，不把若干边际区间误称为未经构造的联合置信区间。

稳健重解对联合参数域执行策略重优化，点估计策略、区间最坏策略和最坏利润范围分别保存。固定随机种子下的情景重抽样逐次保存策略轨迹，并输出决策一致率、逐轮收敛序列和样本计数账本。由于起点是登记情景而非企业观测，本问只支持方法演示和条件决策分析，不声称完成真实批次重解。

## 上一轮审计问题处理

参数字段不一致已通过统一扁平案例适配器修复，零件单价和检测成本在问题二及问题四均进入目标函数。问题二和问题三闭环模型均设置吸收交付边界，并在求解后检查谱半径、单位期望成本、Bellman 残差及事件账本残差。

图一边表缺口不能由代码凭空补造，因此正式题图结果保持阻断状态，只输出相互隔离的主拓扑情景和替代拓扑情景；网络引擎同时支持由显式父节点边表定义的一般有限有向无环装配结构。问题四真实观测缺失同样不被插值伪装，代码生成并保存完整情景样本账本，所有下游字段保持情景限定。

节点单位成本已统一为 `U_v=C_v/Q_v`，成品检测、报废、调换和拆解分支不再被删除；退化网络逐策略对照为阻断式检查。置信区间端点、Bonferroni 构造、逐参数样本量设计和可复现重抽样均已落实。入口所需参数名称全部直接定义并从参数模块导入，避免运行期动态别名回退再次造成缺失。

## 结果解释与使用限制

策略变化由完整事件利润决定，不能仅凭检测费与局部预期损失的表面比值解释。参数改变后程序重新求最优策略，因此结果表区分“固定策略价值变化”和“最优策略翻转”。平局结果使用参数模块中登记的确定性顺序处理，不依赖运行平台或未固定的迭代顺序。

问题一的备择幅度和第二类错误上限是建模设计风险参数，不是题面额外事实；其灵敏度表应与基准结果一并解释。问题三只代表已登记条件拓扑，问题四只代表已登记情景生成过程。所有收入和利润均按一次最终合格交付归一化，金额序列与决策序列分别保留，禁止将单次投入成本率误写为单位合格交付利润。
