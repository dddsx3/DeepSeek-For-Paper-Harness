# 阶段 3 代码真跑结果说明

## 运行与唯一取数规则

`code/main.py` 依次同步执行 `problem1`、`problem2`、`problem3` 和 `problem4`，将各求解器返回的结果统一写入工作目录下的 `outputs.json`。程序成功运行时，四个问题均必须返回非空结果；任一求解器出现阻断性异常时，异常信息写入 `run_failures.json`，进程以失败状态结束，不把不完整结果伪装成可交付结果。标准输出只用于显示运行状态，论文和后续阶段所需的数值均以 `outputs.json` 为唯一机器结果源。

`DELIVERABLES.json` 中的 `ledger_keys` 是后续取数清单，不构成第二套数源。本文不重新心算或手工抄写求解结果；所有数值、数组、验证误差和通过标志均应从 `outputs.json` 对应字段读取，并由后续结果摘要生成器写入论文材料。题面事实和登记设计常数统一从 `code/params.py` 取得，求解器不嵌入另一套输入。

## 问题一：精确二项方案与有限 SPRT

问题一使用 `Q1_NOMINAL_RATE`、拒收置信约束、接收置信约束以及登记的设计风险参数。所有尾部概率均由精确二项质量函数逐项求和，不使用正态近似，不把经验样本量写成输入常数。整数样本量和整数临界值按由小到大的顺序枚举，并保留可复核的平局规则。

拒收结果明确拆成两个口径。`Q1_CASE95_REPORTED_BASIS` 对应的运营方案同时使用 `Q1_ALTERNATIVE_DELTA` 和 `Q1_TYPE_II_ERROR`，因此其样本量同时依赖题面标称率、拒收置信约束以及登记的备择功效约束；该字段带有 `registered_operational_power_design` 标识。`Q1_CASE95_NOMINAL_ONLY_BASIS` 对应的方案只使用题面标称率和题面拒收置信约束。二者在 JSON 中分别保存，不能把运营方案误写成仅由题面条件唯一确定的最小样本量。

接收方案保存最小可行样本量、整数接收临界值及标称率处的精确接收概率。有限 SPRT 使用登记的对数似然比边界和截断上限，逐次记录接受、拒收、继续抽样和截断状态，并以期望检测次数与固定样本方案比较；无上限 SPRT 不作为主方案。超标幅度和第二类错误的灵敏度网格完整写入 `problem1.sensitivity` 数组，数组中的参数值、样本量、临界值和尾部概率均由程序计算并保留。

## 问题二：两零件闭环与事件现金流

问题二对 `Q2_POLICY_SPACE` 中全部二元策略逐一枚举。每个策略均先建立 `empty`、`good`、`bad` 零件状态，检查终止概率和吸收性，再求解 Bellman 状态方程；非吸收策略不参加最大值比较。独立事件账本同时记录采购、零件检测、成品检测、装配、拆解、报废、市场收入、调换损失和补发生产事件。报废不确认任何残值，回收件免采购收益只通过状态转移体现一次。

上一轮指出的零件检测重复计费问题已按状态拆分处理。`empty` 状态首次进入零件检测时，直接执行几何采购—检测循环；检测策略的期望采购数和期望检测数均按失败率的几何循环计算，准备费用为相应采购与检测费用之和除以成功概率。只有已经存在的 `bad` 回流件才先发生一次重检，再进入补充流程。`empty` 分支不再额外增加一次无依据的首检。结果账本保存该转移的期望采购数、检测数、准备费用和目标状态，六种表 1 情形及全部策略均在修正后重新计算。

单位利润口径为元/合格交付。市场收入只在合格交付事件记一次；调换损失只在不合格品退回事件记一次；退回品的补发采购、检测和装配成本另行进入生产账本。由此可区分“调换本身的附加损失”和“生产补发品所需成本”，避免把调换损失重复当作补发成本。策略表还保存每个状态的终止概率、Bellman 残差和状态值与事件账本之间的差值。

## 问题三：一般装配网络与根节点分支

问题三使用登记的有向无环图、节点条件次品率和事件转移核。节点次品率按“父输入均为合格时的条件装配次品率”计算，不把不同来源的次品率简单相加。节点成本严格区分每次投入成本 `C_v`、每次投入合格产出率 `Q_v` 和单位合格产出等效成本 `U_v=C_v/Q_v`；父节点转移使用事件轨迹产生的一次投入现金成本，绝不把 `U_v` 再次乘以 `Q_v`。当 `Q_v` 为零时，节点被标记为无法形成合格产出，策略不进入主比较。

根节点无论是否检测，都进入完整的失败处置事件流。未检测时，不合格根产出仍须经过调换退回和后续处置；检测时，不合格根产出直接进入报废或拆解分支。拆解费用、回收件重新进入生产、再次检测和再次装配均进入同一现金流。`U_f` 不再被错误地固定为单轮装配费，根节点单位利润和父节点转移使用相同的 `C/Q` 口径。

图 1 原件及其可校验边表没有作为阶段输入提供，因此本阶段不伪造图 1 的正式父子关系。程序强制运行 `primary_conditional` 和 `alternative_conditional` 两套由登记边表形成的情景，并输出二者的策略、单位利润、节点指标和利润差异；结果标题和说明均使用“条件拓扑情景”，不把它们表述为已识别的原图答案。退化网络另行逐策略比较两零件模型，保存 `degenerate_max_error`、最大 Bellman 残差、单位成本恒等式误差和根节点分支核对结果。

## 问题四：情景抽样、区间和稳健重解

问题四明确采用 `Q4_DATA_MODE=auditable_scenario_not_observed`。程序先为每个参数节点生成并保存 `(n_v,x_v)`，再计算 `p_hat_v=x_v/n_v`；登记的情景次品率只作为抽样生成中心，不直接充当点估计。`sample_ledger` 必须能够由节点、样本量和计数唯一复算点估计，且不把情景结果称为真实生产批次观测。

各节点独立执行区间精度样本量设计，使用 `Q4_WIDTH_TARGET`、`Q4_N_MAX` 和 `Q4_SAMPLE_SIZE_GRID`，不把问题一的检验最小样本量直接套用为所有节点的区间样本量。样本量扫描结果保存区间宽度、点估计、稳健策略和决策翻转指标。Clopper–Pearson 区间对 `x_v=0`、`x_v=n_v` 和内部计数分别处理：零计数显式返回下端点， 全计数显式返回上端点，内部计数才调用 Beta 分位数。边界测试和精确二项反演交叉核验结果写入验证字段。

联合构造使用 Bonferroni 矩形域。问题二和问题三分别依据 `Q2_PARAMETER_COUNT` 和 `Q3_PARAMETER_COUNT` 分配边际错误率，边际区间集合的联合覆盖口径由 `Q4_JOINT_CONFIDENCE_LEVEL` 和 `Q4_FAMILY_ALPHA` 固定。结果不把多个边际区间未经说明地称为联合置信区间，而是称为联合域下的稳健利润包络。

每次情景抽样均重新求策略，不复用上一轮的最优组合。点估计策略、区间最坏策略、重抽样策略轨迹和决策一致率分别保存；Jeffreys 后验参数由登记常数提供，随机过程使用固定种子和登记重复次数。决策一致率不是监督学习分类准确率：没有训练集、测试集或用蒙特卡洛重复结果反向调参的步骤；每次重复只依据事先固定的抽样机制生成情景，基准策略在重复开始前确定，因此不存在数据泄漏。若将来替换为真实观测，应在策略选择前固定真实样本账本，并重新进行全部区间和重优化。

## 审计问题处理记录

**零件检测分支重复计费。** `empty` 与已有 `bad` 回流状态已分开建模；首件不存在额外首检，回流坏件才计重检。相关期望采购数、检测数和准备费用进入 `problem2` 的转移明细，并由事件账本重新核验。

**图 1 权威边表缺失。** 未补造未提供的图 1。正式图证据缺失被保留为主拓扑条件情景限制，替代拓扑作为强制对照；正式原图结果不被冒充。

**问题一复合运营约束与题面约束混淆。** 运营方案和 nominal-only 方案分别输出、分别标识。运营方案的 `p_alt`、备择幅度和第二类错误均显示为登记设计风险，不能把其结果称为题面唯一答案。

**结果说明缺少真跑摘要。** 本文不手工填入未经执行的值；摘要字段、单位和数组路径均绑定 `outputs.json`，运行时可自动生成问题一 n/r/c、问题二逐情形策略与利润、问题三条件情景指标、问题四稳健策略与一致率。

**问题三单位成本混用。** 所有可产出节点统一执行 `U_v=C_v/Q_v`，包括未检测中间节点和根节点；父节点不使用 `U_vQ_v`。单位恒等式和两零件退化逐策略差值均为阻断式验证。

**问题三根节点失败分支遗漏。** 根节点未检测、检测后报废、检测后拆解、市场退回、调换补发和回收再生产均进入同一事件流；相关验证字段阻断根利润失真。

**问题四缺少真实样本。** 每个节点均保存情景生成的 `n_v,x_v`，点估计由计数比值得到；结果明确标注为情景分析，不把参数中心直接当作观测估计。

**Clopper–Pearson 极端计数失效。** `x=0`、`x=n` 和内部计数均有显式分支及测试结果，未使用形状参数为零的未定义分位数。

**联合覆盖口径不足。** 使用 Bonferroni 联合域，按问题二和问题三各自的参数节点数分配边际错误率；稳健利润只解释为该联合域内的最坏包络。

**问题四复用问题一样本量。** 每个参数节点按区间宽度目标独立选择样本量，并输出样本量扫描、宽度和策略稳定性数组。

**源代码、账本和独立核验不足。** `main.py`、逐问题求解器、`params.py` 和机器输出共同构成可复核链条；验证数组保存 Bellman 残差、现金流差、单位成本误差、退化差值、CP 边界测试、联合误差率和一致率。超过登记容差的结果不得进入后续结果表。

## 验证与失败处理

问题一检查精确尾概率、整数阈值范围、OC 函数单调性和有限 SPRT 截断行为；问题二检查吸收概率、Bellman 残差、状态值与事件账本差值以及空状态/回流状态检测计数；问题三检查图结构、节点可达性、`C_v/Q_v` 单位关系、根节点处置分支和退化模型逐策略等价；问题四检查样本计数合法、点估计可复算、CP 端点次序、Bonferroni 边际错误率分配、每次重优化和一致率轨迹。

所有验证结果均以 JSON 字段保存，包括最大误差、误差容差、布尔通过标志、失败原因和对应索引。只有通过阻断条件的模块才可被论文结果阶段引用；`run_failures.json` 存在时，不得把部分输出解释为完整结果。

## 诚实边界

问题一的运营拒收样本量依赖登记的备择幅度和第二类错误设计参数，因而必须与仅按题面尾部约束得到的方案区分。问题三的图 1 原始父子边表仍缺失，主拓扑和替代拓扑均为条件情景。问题四没有真实节点观测，样本量、计数、点估计、CP 区间、Jeffreys 重抽样和决策一致率均属于可复现情景分析。后续若取得带来源的原图边表或真实 `(n_v,x_v)`，只需替换输入并重新运行，不得沿用本阶段的旧数值。
