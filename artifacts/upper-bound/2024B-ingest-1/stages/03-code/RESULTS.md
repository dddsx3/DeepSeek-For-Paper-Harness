# 阶段 03 编程实现结果说明

## 执行与数值读取约定

本阶段结果由 `code/main.py` 同步执行产生。执行入口依次完成问题一至问题四的求解、结构核验、随机情景重解和总账汇总，并将论文所需标量、数组、状态记录、样本账本及核验结果写入工作目录中的 JSON 文件。标准输出只用于显示运行状态，不作为数值来源。

`RESULTS.md` 不手抄计算值，以免正文与机器总账发生漂移。各结果的确切 JSON 路径由 `DELIVERABLES.json` 的 `ledger_keys` 唯一给出；阶段四只能按这些逐字路径取数。总账中同时保存 `validation` 区域，列出概率范围、Bellman 残差、现金流复算差、退化网络差值、置信区间端点次序、联合错误率和可复现性等核验项。硬约束未通过时，程序返回失败状态，不应把相应问题解释为已完成。

本阶段没有绘图、渲染或图表声明，也未生成任何图像字节。

## 问题一：精确二项检验与有限 SPRT

拒收方案按样本量由小到大搜索，并在每个样本量下完整枚举全部整数拒收阈值，而不是遇到第一个满足第一类错误约束的阈值后提前停止。只有某个阈值同时满足标称率处的拒收尾概率约束和登记备择率处的功效下限时，该样本量才被判为可行；同样本量下按预登记的词典序规则选择阈值。结果锚点为 `R-Q1-case95-n`、`R-Q1-case95-r`、`R-Q1-case95-reject-tail` 及相应的备择端功效。

接收方案已改为非退化单侧检验。求解时强制接收临界值小于样本量，保证拒收域非空；同时使用参数注册表中明确登记的接收备择率和功效门槛，不能再以“接收全部样本”的规则冒充合格率识别。最优接收方案及其标称率处接收概率分别由 `R-Q1-case90-n`、`R-Q1-case90-c` 和 `R-Q1-case90-accept-tail` 承载。

总账保留了 OC 概率序列、标称备择幅度与第二类错误风险网格、整数阈值枚举轨迹以及有限 SPRT 的边界随机游走结果。有限 SPRT 使用与固定方案一致的概率约束和预先登记的截断规则，并分别计算标称率及备择率下的期望检测次数。是否采用 SPRT 由精确尾部约束和两种率下的期望检测次数共同决定，对应 `R-Q1-sprt-expected-n` 与 `R-Q1-sprt-selected`，不以图形观感代替数值选择。

## 问题二：两零件闭环事件决策

问题二以 `empty/good/bad` 零件状态建立完整事件递推。每个策略均覆盖采购、零件检测、装配、成品检测、上市、退回调换、报废、拆解和回收件重新进入生产等分支。检测出的零件次品采购款不回收；报废不产生残值；拆解件仅通过状态转移获得免采购效果；市场收入只记一次；调换损失与补发品生产成本分别记账。

不检测零件的事件核明确使用 `P(good)=1-p` 和 `P(bad)=p`，并保留概率边界测试。六种表 1 情形均枚举全部策略，通过吸收性检查后比较单位最终合格交付的期望利润。每种情形的方案和利润由 `R-Q2-case1-policy` 至 `R-Q2-case6-profit` 对应的结果键承载，完整策略对照由 `R-Q2-sixteen-policy-table` 承载。

状态方程结果还接受独立逐事件现金流账本复算。总账保存最优策略的采购、检测、装配、拆解、调换损失和市场收入分解，并保留检测成本、拆解费用、调换损失及次品率变化时的完整策略价值序列。策略参数改变后重新求全局最优值，因此可以区分固定策略价值变化与决策翻转。成本扰动、状态概率和调换路径的核验结果均进入 `validation` 区域。

## 问题三：一般装配网络及数据缺口

图一原件和可校验父节点边表没有进入上游材料，因此代码不再把自行登记的分组推断称为题图“主拓扑”，也不输出冒充正式题图答案的最优策略或利润。正式问题三状态在总账中明确标为数据阻断；条件拓扑如仍用于方法演示，必须带有条件情景标识，并与正式结果隔离。问题四中的问题三重解同样保持阻断状态，直至获得原图或经核验的唯一边表。

一般网络引擎仍执行以下结构核验：

- 策略向量与映射接口采用零件检测决策、各半成品检测和拆解决策、根节点检测和拆解决策的完整维度，并在主替条件网络及两零件退化网络上执行向量往返测试。
- 每个节点的每次投入合格产出率 `Q_v` 与每次投入现金成本率 `C_v` 来自同一事件轨迹；`U_v` 只按 `U_v=C_v/Q_v` 换算为每件合格产出等效成本，不再与 `Q_v` 重复相乘。
- 未检测分支同样使用完整递推并除以相应合格产出率，不能把单轮投入成本直接冒充单位合格成本。
- 根节点无论是否检测，失败处置、调换、报废和拆解分支均进入同一事件方程。
- 两零件退化网络逐策略与问题二独立事件模型比较，最大绝对差写入 `R-Q3-degeneration-max-error`，并与登记容差比较。超容差会阻断验收。

条件拓扑的节点序列、策略对照及利润差只用于结构敏感性诊断，不构成缺失题图的结构识别结果。条件利润差对应 `R-Q3-topology-profit-gap`；在正式拓扑缺失时，不得用该数值填写 `R-Q3-primary-policy` 或 `R-Q3-primary-profit`。

## 问题四：情景抽样、精确区间与稳健重解

问题四没有真实节点样本。代码先按登记的情景次品率、精度样本量规则和固定随机种子生成并保存每个节点的 `(n_v,x_v)`，再以 `p_hat_v=x_v/n_v` 重做问题二。情景率只作为样本生成中心，不直接充当点估计。所有情景结果均明确标为情景分析。

逐参数样本量根据 Clopper–Pearson 区间总宽度目标独立选择，不复用问题一的最小检验次数。总账保存样本量扫描、区间宽度、点估计策略、区间最坏策略、策略翻转率和利润包络。Monte Carlo 部分保存重复抽样轨迹或收敛轨迹、固定随机种子、Jeffreys 后验重抽样参数及决策一致率；一致率不是只保留的单个标量。

Clopper–Pearson 区间对无次品、全次品和内部计数采用显式分支。端点必须满足概率范围和 `L≤p_hat≤U` 的次序约束，并与二项精确反演定义交叉核验。问题二和问题三分别按登记的参数量分配 Bonferroni 边际错误率，联合域的覆盖口径是保守的族错误率控制，不把多个边际区间误称为同时具有原始置信水平的联合区间。

六种问题二情景的点策略、稳健策略和利润区间由 `R-Q4-case1` 至 `R-Q4-case6` 的对应结果键承载。问题三因正式拓扑缺失，只保存阻断状态和可复现的数据缺口，不生成虚假的稳健策略。决策一致率由 `R-Q4-decision-consistency` 承载。

本阶段没有监督学习训练和测试集划分，也不存在把测试标签用于拟合的分类流程。决策一致率是固定情景生成机制下的重抽样指标，不是监督分类准确率；名义概率只控制情景抽样中心，每次重决策均从该次生成的 `(n_v,x_v)` 重新计算。

## 结果归因与解释规则

问题一的“最小检测次数”只由精确整数约束下首个可行样本量决定；同一可行域内阈值的选择由登记平局规则决定。问题二的最优方案由完整状态价值和现金流账本共同决定，局部“检测费用除以避免损失”只可作为解释性探针。问题三的条件情景差异只能归因于假设边表，不能归因于缺失的题图。问题四的策略变化和利润区间必须结合样本计数、区间构造及重抽样轨迹解释，不能把情景生成中心误写成真实观测估计。

## 诚实边界

问题一的备择幅度和第二类错误门槛属于可修改的建模设计常数，不应解释为题面直接给定值。图一边表缺失使问题三及其问题四重解保持未完成，条件情景不能替代正式题图答案。问题四使用明确生成规则的情景样本，不是企业真实批次观测。生产决策还受静态策略、即时回流、检测全准确、缺陷独立、无容量约束及报废零残值等上游假设限制。
