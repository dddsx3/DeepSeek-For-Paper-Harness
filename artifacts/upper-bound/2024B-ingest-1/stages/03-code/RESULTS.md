# 阶段三编程实现结果说明

## 执行方式与产物

`code/main.py` 是唯一编排入口，按问题一、问题二、问题三、问题四的固定顺序同步执行各模块。入口先校验参数契约并清除旧产物，再调用每问的 `run()`、`validate()` 与 `self_test()`；任一必需字段缺失、结果为空、数值非有限、案例行数不符或结构核验失败时，程序均抛出异常并以非零状态退出，不会留下被误认为有效的聚合结果。

每次执行在工作目录生成：

- `problem1_results.json`：问题一精确二项设计、有限 SPRT 对照、灵敏度与核验结果；
- `problem2_results.json`：问题二六种情形、全部策略及现金流核验结果；
- `problem3_results.json`：问题三条件拓扑、网络指标、退化等价与阻断状态；
- `problem4_results.json`：问题四情景样本、区间、稳健重解与一致率结果；
- `outputs.json`：上述四问结果的严格 JSON 聚合账本；
- `execution_summary.json`：执行顺序、产物名称、问题二回归行数及总体通过标志。

聚合文件采用原子写入，禁止 `NaN` 和无穷值等非标准 JSON 记号。内部遇到零产出率时，策略按无效处理并在 JSON 中记录排除状态，而不是写入非标准无穷值。所有供论文和后续阶段使用的数值均以这些运行产物为准，本文不进行人工二次计算或抄录。

## 统一数值与现金流口径

概率和比例均无量纲；抽样次数与产出率按件或次记录；金额按元/件记录；问题二至问题四的单位期望利润按元/合格交付记录。问题三每次投入的现金成本率记为 `C_v`，合格产出率记为 `Q_v`；仅当 `Q_v` 为正时计算单位合格成本 `U_v=C_v/Q_v`。`U_v` 不再与 `Q_v` 重复相乘，也不替代父节点事件转移中的现金成本。

市场收入只记一次；购买、零件检测、成品装配、成品检测、拆解和调换损失均按实际事件进入同一账本。报废不恢复采购投入，调换损失不替代补发合格品的生产成本。无检测的失败成品先进入市场，再经实际退回事件进入调换和后续处置分支；检测出的失败成品则直接进入同一失败处置系统。

## 问题一结果

问题一直接枚举二项分布尾概率，不使用正态近似。拒收方案按样本量递增搜索整数临界次品数，并同时核验标称率处的拒收尾概率与登记备择率处的功效；接收方案按相同方式搜索整数接收阈值。标称率、可识别超标幅度和第二类错误上限来自 `code/params.py`，其中备择幅度及第二类错误属于登记的设计风险参数，不冒充题面直接给定事实。

`outputs.json` 的 `problem1` 对象保存最小整数样本方案、整数临界值、标称率尾概率、备择端功效、OC 曲线、样本量与信度序列、有限 SPRT 边界、期望检测次数、最终方案选择以及超标幅度和第二类错误的灵敏度结果。有限 SPRT 使用似然比随机游走和预先登记的截断规则；只有精确尾部约束通过且两种率下的期望检测次数均满足比较规则时，才可替代固定样本方案。

问题一同时输出固定阈值的概率单调性、整数搜索首个可行解、精确枚举残差和 SPRT 尾部复核结果。相关数组保留完整参数序列，而非只保存获胜方案的单个标量，供后续阶段直接读取。

## 问题二结果

问题二对两零件状态及终止交付状态建立吸收型事件马尔可夫奖励模型。零件状态区分缺失、合格与不合格；一次合格销售后进入终止状态，不再回到生产状态。每个固定策略均完整覆盖不检测零件、检测后丢弃、装配、成品检测、市场退回、调换、报废和拆解回流路径。

`outputs.json` 的 `problem2.cases` 按表一情形逐行给出 `policy` 与 `profit`，并保留各情形的完整策略表、吸收性信息、状态残差、事件现金流残差、逐项成本和灵敏度结果。最优策略由全部策略的单位合格交付利润重新取最大值得到，不以检测费与局部损失之比代替全局决策。

六种情形的参数适配器显式支持 `price1`、`test1`、`price2` 和 `test2`，并兼容嵌套参数模式。`code/main.py` 会在求解前检查全部案例的参数字段，在求解后检查案例行数以及每行的 `policy`、`profit` 字段，从而阻断此前扁平参数模式导致的缺字段或漏算问题。

所有题面单列成本和损失均进入实际事件路径：不合格检测件的采购款不退还；零件检测和成品检测分别计费；每次装配、拆解和失败交付均计费；调换损失与补发生产成本分开核算。事件账本与状态方程逐策略交叉核验，二者差值必须满足 `code/params.py` 登记的现金流绝对容差。

## 问题三结果

问题三网络引擎以父节点映射和拓扑序为输入，执行有限有向无环图校验、节点可达性检查、节点级策略搜索及完整失败处置，因此不把实例固化为某一组层数和父节点输入数。节点次品率按正品父输入下的条件装配次品率计算，节点策略、产出率、投入成本率和单位合格成本均来自同一次事件口径。

图一原件及可校验父节点边表仍未提供，因此 `Q3_OFFICIAL_EDGE_LIST` 保持为空，正式题图实例状态保持阻断。`3/3/2` 主拓扑和输入数不同的替代拓扑只作为相互隔离的条件情景；问题三结果中的主情景、替代情景及拓扑差异不得改称原图答案。问题四中的问题三重解同样继承这一边界。

每个节点计算 `Q_v`、`C_v` 和 `U_v=C_v/Q_v`。根节点无论是否执行检测，失败处置、调换、报废、拆解和补发路径均进入同一事件模型。`outputs.json` 的 `problem3` 对象保存两套条件拓扑的策略、利润、节点级成本和产出率、拓扑利润差以及完整结构核验信息。

退化网络将相同参数和问题二的两零件模型逐策略对照。`problem3.degeneration_check.passed` 只有在全部策略的单位利润、收入和逐项现金流均满足登记容差时才为真；`main.py` 将该字段作为聚合前的阻断条件。

## 问题四结果

问题四没有企业实际批次的 `(n_v,x_v)` 观测，故 `Q4_ACTUAL_SAMPLES_AVAILABLE=False`，所有输出均保持 `scenario_only=true`。登记情景率只作为二项情景样本的生成中心，不直接作为点估计。代码先保存每个节点的样本量和观测计数，再以 `x_v/n_v` 形成点估计。

各参数节点根据 Clopper–Pearson 区间总宽度目标独立选择样本量，不复用问题一的假设检验样本量。区间计算对零次品、全次品和内部计数分别处理，内部计数使用 Beta 分位数，边界计数使用合法闭区间端点。结果中同时保留样本量扫描、区间端点与宽度、逐节点样本账本、点估计策略、区间最坏策略、利润上下界和重抽样轨迹。

联合构造采用 Bonferroni 矩形：族错误率按参数节点数分配到各边际区间，Q2 与 Q3 分别使用各自的参数节点数。结果不把多个边际区间误称为未经构造的联合置信区间。每次情景重抽样后均重新优化策略，不沿用点估计策略。

问题二重解覆盖全部表一情形；问题三重解只针对登记的条件拓扑情景。决策一致率比较每次情景点估计策略与预先锁定的情景中心策略。若该比例较高，其防泄漏口径是：情景中心只用于生成外层二项样本，不参与点估计拟合；Jeffreys 后验抽样在获得 `(n_v,x_v)` 后独立进行；所有候选策略均在同一评价规则下重优化。该指标属于可复现情景稳定性，不是真实生产数据上的预测准确率。

## 下游所需数组

运行账本保留了问题一的 OC 序列、信度样本量序列、SPRT 边界和两情形对比序列；问题二的全部策略矩阵、六情形结果、最优策略成本分解、缺陷率与成本灵敏度序列及参数平面结果；问题三的节点对比、策略对比、网络成本记录和主替拓扑差；问题四的逐节点样本账本、区间宽度样本量曲线、利润包络和重抽样收敛轨迹。后续阶段应按 `DELIVERABLES.json` 中逐字登记的 JSON 路径取数，不从本文反推数值。

## 上一轮审计事项处理

1. **问题二扁平参数适配**：已在参数属性、问题二适配器和问题四规范化路径中支持 `price1/test1/price2/test2`，并在聚合入口执行六情形回归检查。
2. **问题二缺少吸收状态**：已设置明确的合格交付终止状态，成功销售不再返回生产状态；状态方程求解前检查吸收性，求解后检查 Bellman 残差和事件账本。
3. **问题三图证缺口与通用性**：正式边表继续为空，不伪造题图结论；网络引擎改由父节点映射驱动并校验 DAG，条件拓扑与正式状态隔离。
4. **问题四无实际样本**：保留实际样本缺失标志，全部结果标记为情景分析，不把情景中心称为观测点估计。
5. **问题三单位混用**：`U_v` 统一为 `C_v/Q_v`，零产出策略剔除；父节点不使用 `U_vQ_v` 重复计价。
6. **问题三根节点分支遗漏**：无论是否检测根节点，失败处置和市场退回路径均进入完整事件模型；退化网络逐策略核验对问题二。
7. **问题四伪观测**：唯一抽样输入为已保存的 `(n_v,x_v)`，情景率只负责生成计数，点估计与区间均可由样本账本复算。
8. **Clopper–Pearson 极端端点**：显式处理 `x_v=0`、`x_v=n_v` 和内部计数，边界测试失败时阻断输出。
9. **联合覆盖口径**：采用 Bonferroni 构造并按各问题参数节点数分配边际错误率，输出称为联合置信域下的稳健利润包络。
10. **问题四样本量误用**：逐节点按区间宽度目标选样，并输出样本量扫描和稳定性变化，不使用问题一最小检验次数代替精度设计。
11. **可复核性不足**：源码、逐问 JSON、聚合 JSON、执行摘要、策略全表、验证差值和通过标志均进入交付；关键容差超限或汇总断言失败会非零退出。
12. **问题一参数别名导致运行失败**：`params.py` 已提供缺失别名，编排入口在导入求解模块前执行必需常量预检，防止再次出现同类启动失败。

本阶段不训练分类器，不产生分类准确率；若决策一致率在后续结果中达到较高水平，其情景生成、样本锁定、重新优化和防泄漏口径仍按上节执行。本阶段亦不生成图像字节、渲染代码、数源声明或图表声明。
