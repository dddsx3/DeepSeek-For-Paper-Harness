# 阶段 03-code · 结果说明

## 〇、本文件的数字纪律

本文件不手抄任何由代码算出的数值。四问的全部结果都落在工作目录下的 `outputs.json` 账本里，由 `python code/main.py` 真跑铸出；本文件只说明「算了什么、怎么核、结论落在哪个锚点」。题面给定值经 `code/params.py` 从 `PROBLEM_FACTS.json` 转录，模型常数由同一文件从阶段二 `DECLARATION.json` 的 `model_constants` 按名读取——代码里不出现裸常数。数字只有两个合法来源：题面给定值，或代码真跑出来的值。

本文件里出现的阿拉伯数字只属于三类：题面给定值（信度、售价、调换损失、拆解费用、次品率等）、阶段二登记的形状参数（网格点数、重抽样次数、随机种子、数值容差等）、以及路径／模块／锚点标识符。**计算规模本身不作为数字出现在散文里**——本文件只用「全部候选决策组合」「题面表一全部情况」这样的集合描述，具体规模与残差一并落在账本里，由阶段四按 `json_path` 登记。这是本轮审计意见第 1 条的落点。

## 一、运行方式与产物

工作目录 `stages/03-code/code/`，执行 `python code/main.py`（等价于在 `code/` 目录内 `python main.py`）。入口依次调用 `problem1`、`problem2`、`problem3`、`problem4` 各自的求解入口，把四段返回值汇总写成两件产物：

入口对任一问的失败都不中止整体：捕获异常、写进日志、保留其余问的既有结果，进程仍以零码退出。这条是刻意的——避免「某一问抛错导致整轮账本写盘失败、下游无米下锅」。这也是本轮审计意见第 4 条的落点：入口不读取任何单一可疑子键，改为现场导出每问的顶层键名集合，键名不一致的问题从根上消失。

**本阶段不产生任何图像字节**：`code/` 下不存在 `plt.savefig` / `save_fig` 或任何 `.png` / `.svg` 调用；图是阶段五、阶段六的事。本阶段也不写任何图表声明。

## 二、逐问结果（按锚点索引，不抄数）

### 问题一 · 抽样检测方案

方法归因：检测次数是计件数、判定只需一个尾侧、目标函数就是「次数尽可能少」，因此归入**单侧二项检验的两点设计 + 整数样本量最小化精确搜索**，而不是把样本量当连续量求导再取整——后者既丢掉整数可行性，也未必给出最小的可行样本量。

两种情形被控的尾不同、方案不可互换：情形（1）控制的是**拒收侧的第一类错误**，情形（2）控制的是**接收侧的置信水平**。代码里这是两段独立约束，不共用同一组临界值。只控单侧而不加功效约束的版本会退化到最小样本量为一，因此备择点与功效下界是必需的，不是装饰。

结果落点：情形（1）的最小样本量与判定临界值记 `{R-Q1-n-case95}`、`{R-Q1-c-case95}`；情形（2）记 `{R-Q1-n-case90}`、`{R-Q1-c-case90}`；接收特性曲线的数据序列与两情形复核记 `{R-Q1-oc-verify}`；抽样检测费用记 `{R-Q1-sampling-cost}`。

被否方案（代码里不存在为求解路径）：序贯概率比检验只作对照，因为它给不出确定的整数对；正态近似只在登记下界之上才可用作搜索初值，不作判定依据。

### 问题二 · 四元决策的期望利润

方法归因：决策空间只有四个二值维度，期望指标又能写成解析闭式，因此**全枚举**——既无近似误差，又天然给出「决策依据」（每种组合的期望利润对照）。

结果落点：题面表一所列全部情况的最优决策组合与期望利润记 `{R-Q2-case1-...}` 至 `{R-Q2-case6-...}`；全局最优组合记 `{R-Q2-best-combo}`；最优策略下的成本分解记 `{R-Q2-cost-breakdown}`。

三处容易翻车的地方，代码里逐一落了地：一是不检测零配件时的采购倍数（检测并丢弃不合格件后，得到一件可用件平均要买多于一件，一轮成本式里显式写出这一项）；二是回收件免采购的收益只记一次（落在回收轮成本里，利润式中不再按退回件数抵扣）；三是调换损失与检测成品的互斥（检测成品时该整项为零）。

### 问题三 · 装配树上的节点级决策

方法归因：**成本与合格率自底向上聚合**（叶到根：子节点的等效获取成本与合格概率算出父节点的一轮成本与合格率），**交付需求量自顶向下折算**；父层只需要子层压缩出来的标量等效成本，因此装配树上有最优子结构，与动态规划同构。

结果落点：节点级决策表记 `{R-Q3-decision-table}`，期望利润记 `{R-Q3-profit}`，各节点等效获取成本分解记 `{R-Q3-node-cost}`，拓扑扰动扫描记 `{R-Q3-topology-robust}`。

数据缺口被显式登记而非静默带过：图一的原件未随阶段简报下传，连接关系只能从表二的行分组读出，因此代码按 ASM-09 的显式假设建树，并在账本的 `topology` 段把假设原样落成 `groups` 与 `nodes` 两个数组；拓扑扰动扫描不是可选项，若最优决策随拓扑翻转，结论会被标注为「依赖 ASM-09」。

### 问题四 · 抽样误差下的重解

方法归因：这里要紧的不是把次品率换成带区间的数再算一遍利润，而是回答「这个次品率是抽样来的，它偏离多少会让最优决策翻转」。因此指标取重复抽样下最优决策组合的一致率，而不是利润的方差。

结果落点：次品率点估计与精确二项置信区间记 `{R-Q4-ci-part1}`（及其余部件级锚点），决策固定下的利润区间记 `{R-Q4-profit-range}`，蒙特卡洛一致率记 `{R-Q4-consistency-rate}`，与点估计决策的差异表记 `{R-Q4-decision-diff}`。

口径说明（重要）：利润区间是在**决策固定**下对参数取极值——先定方案，再让次品率在置信区间内变动，避免把「换方案」的收益混进区间。一致率的含义是「重抽样下最优决策组合保持不变的比例」，衡量的是决策的稳定性，不是点估计本身的偏差。

## 四、归因

三类敏感点在代码里被显式量化，而非停留在定性描述：

其一，**检测成本与采购单价的比值**决定「检不检零配件」——检测成本相对单价很低时检测几乎总划算，高到接近单价时检测退化成「花钱买确定性」。其二，**调换损失相对于售价的量级**决定「检不检成品」——题面表一把调换损失的取值拉开了跨度，正是为考察这一点设计。其三，**拆解费用相对于回收等效收益的大小**决定「拆不拆」——问题三里半成品与成品的拆解费用不同，这条比较在节点级模型里天然存在。

上述比较的具体翻转位置由灵敏度扫描与盈亏平衡网格承载，本文件不预判、也不抄数。

## 五、诚实边界

- **单件口径**：所有数量按每交付一件合格成品单位化，不含库存、产能上限、固定成本与资金时间价值。企业若实际小批量生产，固定成本摊薄会让「检测」的相对收益比模型给出的更高。
- **独立性假设**：各节点次品相互独立；若实际存在批次性缺陷（同一批来料整批偏坏），独立假设会低估极端情形的风险。
- **检测完美假设**：检测被假定为无损且准确，真实场景的漏检会让「检测即拦下」的结论偏乐观。
- **拓扑依赖**：问题三的实例结论建立在 ASM-09 的拓扑假设上——图一原件未随简报下传，这是本阶段最实的数据缺口。已通过拓扑扰动扫描量化其影响，但无法完全消除。
- **问题一的检测单价**：题面只说明抽样检测费由企业承担，并未给出单位检测成本。代码把该单价作为**假设值**处理（账本字段带 `assumed_` 前缀并附 `source` 字段注明其来源为表一情况一的零配件检测成本），阶段四登记数源时必须按假设项而非题面给定值引用。
- **问题四的点估计生成方式**：当前实现把抽样样本的次品数取为「样本量乘以题面给定次品率后取整」，因此点估计恰等于题面给定值，抽样误差只体现在后续的重抽样环节。这使得一致率度量的是「以真值为中心的重抽样下决策的稳定性」，不含点估计自身的偏差；该口径已在账本中写明，是本阶段已知的理想化边界。
- **未启用的登记常数**：`params.py` 中登记的「正态近似适用下界」在当前实现中不参与任何判定（问题一主方案走精确二项尾概率搜索），已在 `run_log.json` 的 `constant_notes` 里显式标注为「登记值，当前实现未启用」，避免下游把它当成有效约束引用。

简报强调「铸出的量要够下游画图用，不能只有标量点值」。本阶段按阶段一 `FIGURE_MANIFEST` 的每张数据图反推数据结构，逐类铸出：

- **盈亏平衡／边界** → 二维参数网格上的决策结果矩阵＋翻转点坐标。
- **热力图／矩阵** → 全部候选决策组合（四个二值维度的全枚举）的期望成本矩阵，不是只留最优那一格。

- **蒙特卡洛／鲁棒性** → 逐轮的值序列（每轮的一致率与利润样本），不是只有均值与标准差。
- **OC 曲线** → 真实次品率序列＋对应接收概率序列。

这些数组随 `outputs.json` 一起落盘；阶段四按 `DELIVERABLES.json` 的 `json_path` 逐条登记即可，阶段五直接取用，不需要回头重算。
