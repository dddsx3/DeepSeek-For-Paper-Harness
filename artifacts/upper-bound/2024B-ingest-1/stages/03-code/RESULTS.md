# 阶段 3 结果说明（编程实现）

## 一、代码结构与运行方式

`code/main.py` 是编排入口，依次调用四个问题模块与一个灵敏度模块：

| 文件 | 职责 |
| --- | --- |
| `code/constants.py` | 模型常数（按 `DECLARATION.json` 的 `model_constants` 键名）与题面给定值（表 1、表 2）的集中登记表 |
| `code/numeric.py` | 二项尾概率表、正则化不完全 Beta 函数与 Beta 分位数（不依赖第三方库） |
| `code/problem1.py` | 问题 1：单侧二项检验两点设计 + 整数样本量最小化搜索 |
| `code/problem2.py` | 问题 2：四元 0-1 决策 16 组合全枚举 + 期望利润闭式 |
| `code/problem3.py` | 问题 3：装配树节点级 DP（自底向上聚合 U/Q），含拓扑扰动扫描 |
| `code/problem4.py` | 问题 4：Clopper-Pearson 区间 + 决策固定下的利润区间 + 蒙特卡洛一致率 |
| `code/sensitivity.py` | 灵敏度扫描、盈亏平衡网格、逐链蒙特卡洛校验 |

运行方式：`python code/main.py`。输出落在脚本同目录的 `code/outputs.json`，
**不依赖 stdout 采集**——脚本把全部结果 `json.dump` 到文件。

## 二、问题 1：抽样检测方案

方法：接收特性函数取二项精确尾概率（不用正态近似做判定），在两类错误约束下
搜索满足条件的最小整数 `n` 及对应判定临界值 `c`。两个情形按题面语义分别实现，
判定方向、被控尾、接收域与拒收域都不相同，不可互换。

- 情形(1) 控制拒收侧第一类错误：`P(X >= c+1 | p_nom) <= alpha1`，
  并在备择点 `p_alt = p_nom + Δ` 处要求功效 `>= 1 - beta`。
- 情形(2) 控制接收侧置信水平：题面语义是“在给定信度下认定次品率**不超过**标称值
  才接收”，对应“`p` 的单侧上置信界 `<= p_nom`”，等价于
  `P(X <= c | p_nom) <= 1 - 信度`；同时在 `p_alt` 处要求误收概率 `<= beta`。

上一轮审计指出原主答案把情形(2)写成了反向约束 `P(X <= c | p_nom) >= 0.90`，
得到退化的小样本解。**本轮已改**：情形(2) 的主答案改取置信口径，落在
`q1.case2_accept`（键 `n_star` / `c_star`），`DELIVERABLES.json` 的
`R-Q1-case2-n` / `R-Q1-case2-c` 也指向它。反向约束被保留为**具名对照**
`q1.case2_accept_supplier_risk_reading`，该条目同时输出其在临界值处的单侧上置信界，
用于说明该口径为什么与题面语义相反（其上置信界高于标称值，无法“以信度认定不超过标称值”）。

其他输出：`q1.sampling_cost`（检测次数 × 单件检测成本，题面未给单件金额，按每件单价
归一化并在条目内注明，费用由企业承担）、`q1.oc_curve`（OC 曲线采样点）、
`q1.sample_size_vs_confidence`（含登记的对照置信水平）、`q1.normal_approx`
（用登记的适用下界标记正态近似在最小 n 处是否可用，仅作诊断，不进入判定）。

## 三、问题 2：四元决策的期望利润

四个二值决策的全枚举（策略组合数等于登记的 `问题2策略组合数`）。闭式解逐项落地：

- 一次装配合格率把两条不合格来源写成乘积；
- 检测零配件时“得到一件可用件需买 `1/(1-p_i)` 件”，采购价与检测费同时按该倍数放大；
- 回收件免采购的收益**只落在** `K_r`（免采购价、仍付再检测费），利润式中不再按退回件数抵扣；
- 调换损失项写成 `(1-q)(1-C) l`，检测成品分支下整项为零；
- 拆解费用 `t`、装配成本 `A`、成品检测成本 `c0`、购买单价、市场售价均进入目标函数。

每个策略额外输出分项成本分解（采购 / 检测 / 装配 / 成品检测 / 拆解 / 调换损失），
并计算分解之和与闭式 `U` 的残差（`max_breakdown_residual`），用作分项恒等式核验。

## 四、问题 3：装配树节点级决策

拓扑按 `ASM-09` 的显式假设（图 1 原件未下传，连接关系从表 2 行分组读出）。
求解用节点级动态规划：每个节点维护 `(U_v, Q_v, Z_v)` 的帕累托前沿，父节点在子节点
前沿的笛卡尔积上枚举自身 `(Z_v, D_v)`，取 `U` 最小者。装配树的最优子结构保证
该 DP 给出全局最优，不需要启发式。

方向与上游 `MS-Q3.method` 逐字一致：**成本与合格率自底向上聚合，交付需求量自顶向下折算**。

输出：`q3.decision_table`（每个节点的 `Z_v` / `D_v` / `U_v` / `Q_v`）、
`q3.profit`、`q3.node_cost`（含 `Kf`、`Kr`、`kappa`、`xi`）、
`q3.topology_robust`（与表 2 参数相容的若干连接方案的重新求解与决策一致率）。

上一轮审计提到“声明了却是死参数”：本轮已把 **`灵敏度扰动幅度`** 真正用进
`code/sensitivity.py`（对表 1 情况 1 的全部关键成本与次品率做上下扰动重解），
并额外用 **`盈亏平衡等高线格点数`** 构造二维检测成本 × 调换损失网格上的决策翻转面。

## 五、问题 4：抽样误差下的重解

上一轮审计指出原实现只覆盖了表 1 的情形 1。**本轮已改**：`q4.q2.cases` 是**按情形编号索引的列表**，
逐条覆盖表 1 的全部六种情形，每一项都带 `case` 号与 `params` 派生量，并对问题 3 的
12 节点装配树单独做一套。

口径：

- 点估计 `p_hat = x / n`；区间用 Clopper-Pearson 精确区间（Beta 分位数表示），
  在小样本与极端比例下有正确覆盖率；
- 利润区间在**决策固定**下传播：固定点估计得到的最优决策，让次品率在置信区间内取角点，
  取利润的最小与最大。这样区间反映的是“同一个方案在最坏/最好参数下会怎样”，
  不把“换方案”的收益混进来；
- 一致率 `rho`：重复抽样下重新求最优决策，统计与点估计决策相同的比例，
  并与登记的判定阈值比对，给出可核验的布尔结论。

抽样口径：题面未给问题 4 的样本量，实现取 `n = 100`、观测次品数按各情形标称次品率
取整（点估计与标称值一致），该取值登记在 `IMPLEMENTATION_PARAMS` 并在输出条目
`q4.sample_size_note` 中再次说明。问题 3 每次重解要跑一遍装配树 DP，因此其蒙特卡洛
重复次数取 `IMPLEMENTATION_PARAMS.q3_mc_reps`（较问题 2 的 2000 次低），
每个一致率条目同时输出 `rate_standard_error`，避免把宽区间当精确比例引用。

## 六、灵敏度与稳健性

- `sensitivity.q1_sample_size_vs_confidence`：样本量随信度的增长形态，含登记的对照置信水平。
- `sensitivity.q2_one_way`：对表 1 情况 1 的关键参数按登记的扰动幅度做上下扰动重解，
  逐条记录最优利润、最优决策与是否翻转。
- `sensitivity.q2_breakeven`：检测成本倍率 × 调换损失倍率二维网格上的决策面（格点数按登记值）。
- `sensitivity.q2_mc_check`：用登记的蒙特卡洛重复次数与随机种子，对表 1 情况 1 的最优
  策略做逐链仿真（逐轮支出、按 `D` 决定拆解或报废、按几何分布累计），与解析闭式解比对。
  这是抓“采购倍数漏记”与“免采购重复计”最直接的手段。

## 七、诚实边界

1. 本阶段不声称任何建模检验“已通过”。`outputs.json` 的 `verification` 段记录的是
   **代码自己算出来的自检布尔量**（约束是否满足、分解残差是否在容差内、节点数与策略数
   是否与登记常数一致、问题 4 是否覆盖全部情形、区间是否包住点估计），
   它们只说明“本实现自洽”，不替代阶段 8 的独立复核。
2. 问题 3 的最优解依赖 `ASM-09` 的拓扑假设。`q3.topology_robust` 已把这一依赖量化，
   但无法消除。
3. 问题 4 的样本量、问题 1 的单件检测费用基准均为题面未给量，已在
   `IMPLEMENTATION_PARAMS` 与输出条目内显式登记；它们不是模型常数。
4. 成本分项分解与逐链仿真只覆盖问题 2；问题 3 的成本流由节点级 DP 的分项字段给出，
   未另写独立复算器。
5. 全部金额单位为元/件，比率为无量纲百分数，与上游 `C-UNIT-DEF` 一致。
