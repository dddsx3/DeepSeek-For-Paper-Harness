# 第三轮实测：知识投递方式与封顶移除（2024B / strict）

> **本轮回答两个问题**：
> ① 参考优秀产品是怎么把知识送到模型面前的？我照它改了什么？
> ② 移除"方法选择"这个封顶之后，模型的**行为**变了吗？**交付物**变了吗？
> **配置**：与前面同题同模型同档位（2024B × `deepseek/deepseek-v4-pro` × `strict` × 档位 A）。
> **日期**：2026-09-22 / 23

---

## 1. 参考实现是怎么做的（只读、只学结构，不搬内容）

我读了它的运行产物（工作区指令文件、实际发出的 prompt、agent 工具日志），结论是
**它既不是"全塞进 prompt"，也不是"交给模型自己决定"**，而是三层：

| 层 | 形态 | 证据 |
|---|---|---|
| **短且永远需要的规则** | **嵌入**工作区指令文件 | 竞赛规则、输出格式、核心原则、风格选择都在指令文件里 |
| **步骤专用的知识** | **就是那一步的指令**（一步 = 一个技能，技能文件即该步的 prompt） | 流水线 11 步，每步一个技能 |
| **参考材料** | **指名 + 说明里面有什么 + 标"必读"/"按需读取"** | `_format_reference.md`（含…规范，**必读**）；题面原文（**按需读取**） |

**关键的一条**：它把"本步骤上下文"**放在指令文件的最后**（最后 = 最高优先级），
字段固定为：目标源文件 / 上游产物状态 / 必读指针 / 本步骤定位 / 必修项 / **不要做** /
**完成标志**。

**并且它的模型确实会读**：agent 日志里有 191 条工具调用，模型自己说"我先读它"
并读了被指名的文件。

## 2. 我因此改了什么（一处我自己引入的真实缺陷）

**第一版 L1 是错的**：我写了"必读：`skills/x.md`，用 `read_file` 读它"——而**本管线的
模型调用没有工具**（`streamCompletion` 只发 messages，不发 `tools`；代码里没有 tool
循环）。模型**读不到**那些文件。那是一条**无法被遵守的指令**，正是这个项目反复抓到的
那类缺陷：判定侧写了，传递侧没写。

**改法**：每一步的简报把它需要的知识**内联**进那一步的 prompt（最后一段），并按参考
实现的字段补齐：目标产物 / 上游状态 / **本步知识（内联全文）** / 本步定位 / **不要做** /
**完成标志**。

**代价是可控的**，因为每一步只内联它自己需要的 1–2 份：

| 步骤 | 内联的知识 | 体量 |
|---|---|---|
| analyze（E1） | **无**（它写散文，不需要容器契约——W8.10-D4 的教训） | 0.3 KB |
| explore | 探索—择优流程 + 方法族手册 | 4.3 KB |
| select | 择优记录格式 + 评分口径 | 3.5 KB |
| produce | 数字通道 + 论文契约 + 写作规范 + 符号纪律 | 10.3 KB |
| review | 评分口径（含"误报会淹没队列"） | 2.1 KB |
| revise | 写作规范 + 论文契约 | 6.8 KB |

**不变量**（有测试钉住）：每一份技能文档的**正文**都必须出现在某一步的简报里
（没有孤儿知识）；产出步必须内联数字与写作纪律；分析步必须**轻**且**不含容器语言**。

## 3. 第二个发现：闭集契约还在，模型正在照它选方法

在 strict-3 的 E1 里，模型**逐字照抄**了 CLI 注入的横幅：

> 根据题型路由，本题适用方法族 **F4（评价决策）**，候选模型集为 entropy / AHP /
> CRITIC / delphi / TOPSIS / gray-relational / fuzzy-comprehensive / weighted-sum

那句话的原文是 `候选模型集(封闭,只能从中选择,禁止自创)`。**这是全案最要命的一处封顶**：
本架构的立论是"建模论文的质量差距大半在选了什么方法"，而这里把选择权拿走了。

同一份 CLI 里还有第二处：方法族路由失败时 **`return 3`（零 token 拒绝）**——那会在
拓展 MCM / 期刊论文时封死整条产线。

**两处都按设计改了**：

| 改动 | 前 | 后 |
|---|---|---|
| 横幅 | `候选模型集(封闭,只能从中选择,禁止自创)` | `## 题型先验 F4（评价决策）—— 参考，不是约束`；候选方法仍列出，但明写**"这不是白名单…本 harness 不对方法选择施加约束"** |
| 路由失败 | `return 3`，零 token 拒绝 | `[ROUTE-DEGRADED]` 标注 + 按 `F5-other`（先验为空）继续 |
| 族验证规则 | `候选模型封闭`（不在白名单即不通过） | `选型已登记`（**任何**非空模型名都通过；不在常见方法内只作提示） |

**被保护的不变量没变**：路由判定仍然先于任何模型调用，结果仍进 run-report；"未声明
模型"仍然不通过（自由 ≠ 可以不说）。

## 4. 效果：**行为变了，交付物没变好**（必须分开说）

### 4.1 行为变了（直接证据，两轮 E1 原文对比）

**strict-3（闭集契约）**：
> 根据题型路由，本题适用方法族 F4…候选模型集为 entropy/AHP/CRITIC/… → 本質上属于 **weighted-sum** 的变体

**strict-4（软先验）**：
> 整体方法族为 F4，**但问题 1 本质上是统计假设检验（F3 的边界）**，问题 2–4 是期望
> 成本/利润驱动的离散决策优化。因此采用"**统计检验 + 期望成本递推 + 策略枚举**"的
> 混合框架

**模型跨出了那个族，并把理由写出来了。** 这正是设计要的效果。

### 4.2 交付物没变好（诚实记账）

| 运行 | 变更 | 拒绝 | REF-003 | 保真门 | 生产链 | 容器结构 | 传输/环境 | findings | docx |
|---|---|---|---|---|---|---|---|---|---|
| strict-1 | 原始 | 7 | 3 | 3 | 0 | 1 | 0 | 63 | ❌ |
| strict-2 | +shared 作用域 | 8 | **0** | 0 | 4 | 1 | 3 | 55 | ❌ |
| strict-3 | +每步内联知识 | **4** | 0 | 0 | **1** | 0 | 3 | **47** | **✅ 58KB** |
| strict-4 | +方法选择自由 | 7 | 0 | 1 | 3 | 2 | 1 | 54 | ❌ |

**strict-4 没有优于 strict-3**（54 vs 47 findings、7 vs 4 拒绝），而且它多烧了
35% 的 token（286K vs 212K）。其中 3 次拒绝是**环境问题**（中转返回 502 的 HTML 错误页、
空流），不该算在架构账上——但另外 4 次（容器结构 ×2、生产链 ×3、保真门 ×1）是真实的。

**为什么行为变了而交付物没变好**：因为**瓶颈不在方法选择**。四轮下来，交付档位
始终是 `DEGRADED`——链从来没有真正走通过一次。方法自由让模型**想得更好**，但
"想得更好"要变成"交付得更好"，得先让 E2 → 生产链走通。

**L3/L4 至今未被触发**（`symbolic_channel_run: 0`、`structure_fingerprint: 0`）：
它们挂在交付链上，链没走到尾。

## 5. 现在剩下的真实瓶颈（四轮一致的证据）

| 拒绝类别 | 出现次数（四轮合计） | 性质 |
|---|---|---|
| 容器结构（`entries` 非空数组） | 4 | 模型输出损坏/截断 |
| 生产链下游（`code run` / `report render` / 散文要素） | 8 | **模型自己声明的瑕疵** |
| `physical key 'S_P1'` 不解析 | **4** | **下划线 vs 连字符**——同一条规则，教了两轮仍未落地 |
| 保真门 B3 反向 | 4 | E1 标了假设但容器没声明 |
| REF-003 全局假设 | 3 → 0 | ✅ 已修 |
| 传输/环境（502、空流、中断） | 7 | 与架构无关 |

**最值得注意的一行是 `physical key 'S_P1'`（4 次）**：这条规则我已经写进宪法
（"`numeric_config.json` 的键用**精确的 token 或 symbol_id**，例如 `S-P0` 而不是
`S_P0`"），模型仍然反复踩。**它不是知识不足，是执行时的粗心**——而这恰恰是
"事后核验 + 有归宿"该兜的东西：拒绝信息直接列出了合法取值，重试就能改对。

## 6. 下一轮该做什么（按信息量）

1. **让链走通一次**，而不是继续加机制。四轮下来交付档位没动过，说明**下一步的
   信息量在"通链"，不在"加层"**。具体：把 `physical key` 与容器结构这两类
   **高频且机械可判**的失败，做成**产出前的自检**（让模型在提交前自己跑一遍
   键名解析与 entries 形状检查）——这比再写一条教学更可能落地。
2. 链通了之后，L3/L4 会第一次被触发，`R_num` 才有基线，三视角评审的价值才可测。
3. `shared: true` 机制**至今未被模型使用**（strict-3 里 13 条假设、0 个 shared）：
   模型走的是"逐子问题各声明一条"的记账路线。两条路线都能过 REF-003，所以结果
   没问题——但这个机制目前是**空转**的，需要决定是保留（作为可选表达）还是移除。

## 7. 判据边界

- **n=1 per 变更**，四轮不能谈分布，只能谈"某类失败消失了没有"。
- **strict-4 的 3 次环境性拒绝**（中转 502 / 空流）不应计入架构评价，但它们确实
  拉长了运行、增加了 token。
- 我**没有**评估论文的建模正确性——本报告只回答"机制是否生效、瓶颈在哪"。
- `costUsd` 恒 0（路由未配价格表），token 是实测的，金额不是。
