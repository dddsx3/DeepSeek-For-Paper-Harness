## 2. 本阶段之前修掉的两处（都不是 E1 本身的问题，但都属于"热重启能不能用"）

### 2.1 `--resume` 印在提示里却没实现

**错误形态**：`renderResumeInstruction` 打印的续跑命令是
`paper-shell run <题> --resume <slicesRoot> --run-id <id>`，而 CLI **根本没有解析
`--resume`**。也就是说：按提示敲那条命令，它会被当成一个未知参数忽略，然后**从头跑一遍**。

**根因**：模块（`stage-checkpoint.ts`）先写好并测过，CLI 侧的接线没跟上。这正是本项目
反复抓到的那一类——**"模块做好了但从入口够不到"**。它的危害在热重启这个场景里特别大：
从头跑会产出**不同的 E1**（模型非确定），于是你审过的那份切片与继续跑的那份**对不上**，
检查就白做了。

**修法**：
- `PaperExecutorOptions.resumeFrom = { analyze?, container? }`：把已检查通过的切片载荷
  **播种**回来。E1 播种进 `#e1ByRun`（跳过 E1 调用），容器播种进新的
  `#seededContainerByRun`（跳过 E1+E2 两段）。
- CLI 解析 `--resume <slicesRoot>`：用 `resumePointOf` 取**已检查通过**的最后一片，
  读它的载荷播种；没有合格切片就**明确拒绝**（退出码 2）并说明原因，而不是静默从头跑。
- 审计记 `resume_seeded`，所以"这一轮跳过了哪些阶段"是一个可核验的事实。

**设计取舍（写下来备查）**：只播种 analyze 与 declare，**不播种 produce 的报告**。
理由是产出链是容器的**纯函数**（同容器 + 同 seed → 同代码输出 → 同渲染结果），
重派生出来的报告与你审过的那一份一致；而播种报告需要伪造一个节点 id
（`draft.nodeId` 被引擎后续使用），得不偿失。**边界**：容器没写 `run.seed` 时产出
可能不同，此时续跑会重新产出，检查者需要重看。

### 2.2 schema 把可选对象物化成空对象 → 审计多出一条事件

**错误形态**：修完 2.1 后全量套件红了 5 条，全部是"审计序列逐字相等"的断言，多出
`resume_seeded`。

**根因**：播种块的门是 `if (this.options.resumeFrom !== undefined)`。而 schema 里
`resumeFrom: s.object({ analyze: s.string(), container: s.container() })` 会把**声明过的
可选对象物化成 `{ analyze: undefined, container: undefined }`**——`!== undefined` 为真，
于是**什么都没播却发了审计事件**。

**修法**：判据从"对象在不在"改成"**真的播了东西**"（载荷存在且非空）。并在注释里写明
"空播种不是播种"。

## 4. 本阶段发现、但**不在本阶段修**的两件事

### 4.1 166 个数字字面量，此刻全部未经代码通道验证

E1 是自由散文，它写的数字（`10%`、`95%`、`90%` 这类题面给定值，以及可能的自算值）
**没有一次代码验证**。这不是本阶段的缺陷——E1 的职责就是想清楚，数字要由后面的
容器 + 代码通道兑现。但它正是 round-6 报告里那条"**伪数字**"风险的源头：如果后续阶段
失败、走了 E1 直通兜底，这 166 个数字就会**原样进交付稿**，而稿子看起来是完整论文。

**已有的防线**（round-6 加的，本轮未验证过）：
- 兜底路径会生成 `unverified_numbers` finding（major），把"这 N 处数字全部未经代码通道
  验证"写进交付附录的已知缺陷表。
- 交付前的防伪守卫要求非 CLEAN 稿子必须带抬头与"未经规范 IR 验证"说明。

**本轮要观察的**：后续阶段真的走通时，这 166 个数字里有多少被 Result 占位符取代。

### 4.2 E1 **零标题行** —— 这条给 round-9 的归因加了一个限定

我在 `FORMAT-AUDIT.md` 里把格式飘移（小节层级消失）归因到 round-9 的降级正则
`.replace(/^#{1,6}\s+(.+)$/gm, '**$1**')`。**这一次运行显示那条归因需要加一个限定**：

本次 E1 **一条 markdown 标题都没写**。也就是说，即便没有那行降级正则，这一次的交付稿
也不会有 `###`——它的零小节是**模型当次没写**，不是被降级掉的。

两条机制因此都存在，需要分开说：
- **(a) 降级正则**：让"E1 写了标题"的那些运行**结构性地**丢掉层级。历史证据是
  round-9 之前有 24 条 `###` 的运行、之后 13 次全为 0。
- **(b) 兜底骨架**：E1 不写标题时，兜底路径的骨架也不发编号小节（它的槽内容里没有
  `###`），于是同样是 0。

**结论修正**：round-9 是**机制 (a)** 的起点，这仍然成立且有代码与产物两层证据；
但"13 次全为 0"里有多少是 (a)、多少是 (b)，**本轮的证据不足以区分**——要区分得看
那些运行的 E1 原文里有没有标题。这一条留作后续核对项，不在本轮下结论。
