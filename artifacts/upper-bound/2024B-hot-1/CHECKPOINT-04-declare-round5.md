## 3. 本轮想验证但没验到的修法

`callWithSelfCheck` 的**批准作用域**修复（W12-C5）：

第四轮（`05-declare`）实测——模型调了 3 次工具，工具第 3 次判 `admissible: true`，
循环收口并要求"把那份文本**原样**给出"。**但模型交回的是一份改过的文本**：
工具批准的是 `evaluation ≥ 800` 的容器，提交的那份是 **671**。

于是"工具批准过"变成了一种**虚假的安心**：批准针对 A、提交 B，而 B 从未被检查过。
这与 round-5 修的"批准后又改"是同一形态，只是那次改在收口**之前**、这次在收口**之后**。

**修法**（不是再写一句更强的措辞——"原样给出"已经写过且无效，这正是本项目反复学到的
"模型不会因为被告知就照做"）：在**返回处**验一次。交回的文本若与批准的那份不同，
**批准对它不适用**，对新文本重跑同一套判据；不过就把问题回灌给它继续改。

新增 2 条测试（41 条自检回归）。**但本轮没有真实运行验证它**——见 §2。

## 4. 防伪守卫拦下一次真实交付（本轮最重要的发现）

### 4.1 发生了什么

兜底路径产出了 E1 直通稿，修订轮跑完，走到交付口——**被守卫拒绝**：

```
DELIVERY REFUSED — 档位 DEGRADED（路径 B-e1-direct）的交付稿缺少防伪标注：
unverified_note。这些标注是这份稿子**唯一**的可信度标记——被剥掉之后它看起来
就是一篇经过验证的论文（实测出现过伪造的验证结论）。拒绝交付，而不是导出一份
没有标记的成品。
```

**守卫做对了。** 它拦下的是：一份**看起来完整、但已经丢掉了自己唯一可信度标记**的论文。

### 4.2 为什么这条重要

round-5 的审计把这类产物称为"**最危险的现存产物形态**"：

> 它看起来是完整论文（有数字、有结论、格式正确），但数字未验证且实测有错。
> 务必保证 DEGRADED 标注在任何导出格式里都无法被剥离——它是这份稿子唯一的防伪标记。

当时（round-6）我核查过四条导出路径（md / pdf / docx / zip）**都保留**标注，
并补了运行时守卫。但那时的结论是"**目前**保留"——**机制上会不会被剥离**没有实测。

**这一轮实测到了**：兜底稿的 `未经规范 IR 验证` 那句标注**确实会消失**。

### 4.3 最可能的机制（下一轮要确认的）

`renderE1DirectDraft` 把那段标注写在**摘要槽**里（`e1-direct.ts` 的 `note`）。
而 round-6 已经查明：**兜底稿之后要过修订轮**（review→revise），修订轮的输入输出
都是自由文本，唯一守卫是 `revisionDestroysDraft`（**标题集合 + 长度 ≥50%**）。
摘要章的**正文被整段改写**不会改变标题集合，也不会让总长度掉一半——**它过得了那道守卫**。

所以：**标注写在"会被自由文本改写的那一章里"，而守卫只看标题和长度。**
这与 round-6 查到的"兜底稿的如实说明被修订轮整章改写"是同一个洞的两个面。

**未做**（诚实列出）：本轮没有定位到具体是哪一次修订抹掉了它——那需要比对
`artifact-bodies.json` 里各轮的修订文本。下一轮第一件事就是这个。

### 4.4 这条与热重启的关系

如果这一轮**没有**守卫，交付包会照常产出（report.md / pdf / zip 齐全），
我会在检查点看到一个"看起来完整"的交付物——而它已经丢掉了可信度标记。
**守卫把这个失败变成了一个响亮的、不可忽略的拒绝**，而不是一个需要人眼去发现的缺陷。

这正是"把判定写成代码"的价值：**它不依赖检查者有没有注意到。**
