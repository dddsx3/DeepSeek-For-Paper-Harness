## 2. 实测状态（诚实）

修完之后，**契约的完整度要求显著提高**，第 18–21 次基线都**没能**在新标准下交出
`A-produce-chain`（全部退回 E1 直通）。逐次观察到的失败点：

| 运行 | 结果 | 卡在哪 |
|---|---|---|
| baseline-18 | B-e1-direct | 5 次尝试分别死在：缺代码附录章 → 代码无产物 → 保真 → 代码无产物 → 缺 methods+问题重述 |
| baseline-19 | B-e1-direct | 缺 methods 章（两次）+ 一次 provider 空流 |
| baseline-20 | B-e1-direct | 无图被拒 → 重发同一容器 → 同因熔断 |
| baseline-21 | B-e1-direct | 保真 → 代码无产物 ×2 → 解析失败 |

**怎么读这件事**：这正是 baseline 该量的东西。修之前，"只答问题1 的论文"能拿到
`A-produce-chain`（第 17 次基线）；修之后同样的稿子会被链上拒绝并点名缺哪几问。
所以：

- **第 17 次基线（baseline-17）** 仍是"首份真实产出的、可导出、证据随稿"的论文——
  可封存为 **v0**，但它**不满足**新的完整度标准（只答问题1、无图），必须带着这个
  标注封存，否则会误导后续比较。
- 新的完整度标准（逐问覆盖 + 图 + 全章 + 数字闭环）就是 **v1 的门槛**。当前模型
  （deepseek-v4-pro）在 5 次尝试内还没跨过去——这是**模型能力读数**，不是机制缺失。
  想跨过去的三条路：加尝试数、换更强的模型、或接受 MARKED 交付（内容不完整但诚实标注）。

## 5. 内容审计（baseline-23 的数字，不是结构）

结构层面 baseline-23 是达标的（四问各有自己的执行结果文件、1 张 OC 曲线、13 章、
0 占位、交付链全绿）。但**把四个数据文件读出来看数字**，结论要冷得多：

| 题 | 交付的数字 | 审计判断 |
|---|---|---|
| 问题1 | `{n: 379, c: 45, prod_risk: 0.0989, cons_risk: 0.0480}` | **自相矛盾**：题面要求"在 95% 信度下认定次品率超标则拒收"，即生产者风险 ≤ 0.05；而这里 prod_risk = **0.0989**，接近 α 的两倍。也就是说这份方案不满足它自己声称满足的信度（第 17 次基线在同一题上给的是 n=29/c=6 且风险合规，本轮换了方法反而更差） |
| 问题2 | `{profit: 2.2, d1: 1, d2: 1, df: 0, dr: 1}` | 一个**真答案**：决策向量 + 期望利润，结构与量级都合理 |
| 问题3 | `{profit: 0}` | **不是答案**：单值 0，没有逐工序决策、没有 8 配件实例结果 |
| 问题4 | `{profit: 0}` | **不是答案**：同上，贝叶斯后验路径没有任何可见产出 |

**所以：v1 在"结构完整"上达标，在"内容可信"上不达标——四问里只有一问答对。**

这不是 harness 机制缺失，而是**越过了 harness 自认的判定边界**：harness 判定的是
"结构完整、数字可溯源、形式化忠实"，不判定实质正确性（W8.9-C2 的口径保留在交付物
里）。`n=379 / prod_risk=0.0989` 是否是对题的正确回答，属于实质正确性——但其中
**有一部分是可以机械化的**，正是审计报告 C-3 那一项：

- 模型可以**声明不变量**（如 `prod_risk <= alpha`、`profit >= 0`、`0 <= c <= n`），
  harness 逐条核对声明值是否满足——`prod_risk=0.0989 > alpha=0.05` 这类自相矛盾
  当场可查，不需要人来读；
- "一个 REQUIRED_OUTPUT 只对应一个常量 0"也可以机械识别（退化产出：无决策结构、
  无不确定度、与同题其它 Result 无关联），作为 DRIFT 退回让模型补做。

**下一轮的头号项因此从 C-2/C-4 换成 C-3**：它是把"数字存在"变成"数字可查"的那一步，
也是当前唯一能拦住 q1/q3/q4 这类交付的机制。
