## 裁决单 1：六桩处置路线（任务书 R1-1 / A-2）

- **背景**：`src/delivery/gate-registry.ts:120-188` 注册了六个 critical producer（`runtime_integrity` / `execution` / `numeric_consistency` / `reference_validation` / `requirement_coverage` / `figure_data_consistency`），reason 已诚实标注 "TASK 4.0 stub" 但 `status` **恒 PASS**（其中 `numeric_consistency` 连 IR 判空都没有）；`numeric_consistency` 为无条件 PASS。INV-3-O 被架空：`producer_unimplemented` BLOCKED 分支（`gate-registry.ts:269-283`）因全库零注册而不可达。九个 critical 门中：`ir_canonicalization`（irBridgeGate）、`provenance`（executionProvenanceGate）、`stale_detection`（computeStaleReport）为真实实现；六桩为假 PASS。
- **选项 A（推荐）**：六桩注册全部改为 `registerCriticalGate(id, UNIMPLEMENTED)`——一个提交内完成、回归面最小；FORMAL/FAST（`backboneRequired=true`）下 policy 对任意 IR 返回 `producer_unimplemented` BLOCKED（机制已存在）；交付立刻"诚实的红灯"。代价：本批次内 FORMAL/FAST **彻底无法交付**（任务书 §7.3 已声明这是可接受的诚实代价，叙事为"结构防御就绪，内容管线未通"）；EXPLORATORY 仍可交付（模式级豁免，非桩）。
- **选项 B**：逐个实现 v0.1 真语义。代价：依赖 P1 排期、本批次无法收口，六桩假 PASS 继续在账上。
- **推荐：A**（诚实优先；门语义实现放 P1 批次逐门推进）。
- **不选 B 的代价**：P1 之前交付层继续在"看似可交付、实则未校验"的假绿上运行——正是本批次要消灭的状态。
- **落地映射**：`src/delivery/gate-registry.ts`（六处注册改 `UNIMPLEMENTED`、删除桩函数体）；新增导出 `criticalGateImplementationReport()`；`tests/delivery/gate-registry-profile.spec.ts` 补登记表断言；RG-09 进 `artifacts/handoff/TASK-2.1/verify-report-state.mjs`。
- **连带决定（执行方记录，R1-1 直接后果，作者 2026-09-03 二次批准）**：六门 UNIMPLEMENTED 后，以 `mode:'fast'/'strict'` 跑 run 并期望交付的 executor 机制类测试会被 `producer_unimplemented` 拦死。核查发现 **`RunMode` 枚举（`spec.ts:34`）只有 `'fast'|'strict'`，没有 `'exploratory'` run mode**——EXPLORATORY 此前只是 guard profile（`RuntimeMode`），run 层不存在。经作者拍板（选项 A），本批次把 `'exploratory'` 提升为一级 run mode：`spec.ts runModeSchema` + `settings.ts defaultMode` + `legacy.ts migrateRunMode` + `cost.ts evaluateBudget`/`executor.ts assertBudget` 类型放宽（budget 同 fast=1×、不加乘数）+ host `api/paper.ts` 视图/start 类型放宽；`resolveRunPolicy('exploratory')` = 3 轮（同 strict，注释写明）。执行器机制类测试（executor.spec / executor-guards / executor-context / executor-resilience / executor-ir-bridge happy-path / provenance-gate E2E / workflow.e2e）迁 `'exploratory'` run + EXPLORATORY guard，断言与意图保留（review 轮次计数按 3 轮调整）；fast=1/strict=3 轮次政策补 `resolveRunPolicy` 纯单测（executor-guards 'policy resolution' describe）；workflow.e2e 的 fast 专项验收记录跟踪项，P1 六门实现后恢复。EXPLORATORY run 的产出"非正式"标记见裁决单 4。
