### 0.3 我核验中发现的三处偏差（汇报未提及）

**偏差一：execute#2 不是截断。**
`execute#2` out = **10,756**，失败码 `schema_violation`（DRIFT）。**10,756 < 32,000，说明模型自己停下来了**——它产出了一个**完整但 schema 不合法**的容器。这与截断是两类问题。所以 D8 报告"失败链由截断驱动"的说法**只覆盖 2/3 次尝试**。修正后的画像：

| 尝试 | 输出 | 失败性质 |
|---|---|---|
| #1 | 32,000 | **截断**（上限） |
| #2 | 10,756 | **完整输出，schema 不合规**（非截断） |
| #3 | 32,000 | **截断**（上限） |

**这条修正直接影响 W9 计划**：只修 `max_tokens` 会留下 #2 类失败。

**偏差二：被拒的容器文本没有被保留，因此 #2 类失败不可诊断。**
仓库原则是"模型可见 ⟺ 已记录"，但被 `ir_producer` 拒绝的原始输出无法从归档中取回。后果：#2 那次 schema 违规**具体错在哪个字段、哪个路径，现在永久不可知**——只能靠猜。这意味着任何未来的协议失败都会同样不可诊断。

**偏差三：指标快照在结构上无法区分 fake 与 real。**
`metrics-snapshot-w8.5.json` 的记录字段是：
`problem_id / family / grade / m1… / m2… / m3a/b/c… / m4… / m5…`

- **没有 `provider_mode`**：所以 `2024-A/B/C`（W1 的 **fake T3** 运行，grade 全是 `CLEAN`）与 `2024-C-real`（真实模型，`BLOCKED`）在同一份数据结构里**无法机械区分**。红线 N2 禁止"把 fake 结果计入真实指标"，但**数据结构没有强制它**——合规目前依赖阅读者的记忆。
- **没有 `routed_family`**：快照记录的是预注册标签 `family: F3`，而路由器实际判的是 **F4**（E3 发现）。所以 E3 只存在于散文，**路由准确率无法被长期追踪**。
- **`m2_silent_errors = 0` 对 BLOCKED 运行会产生误导**：没有交付物 → 静默错误自然为 0。读者可能把 "M2 = 0" 读成好消息。M2 需要**交付条件化**（无交付时记为 N/A 而非 0）。

## §1 裁决：是否进 W9

### 1.1 裁决

**进 W9——但不得直接进。在 W8.6 之后再进。**

W8.5 达成了它自己的目标：**拿到第一个真实信号**。而且这个信号的价值高于"跑通"——它证明了瓶颈在协议形状，不在模型能力。这是点火轮要的东西。

但**你列的三个修法选项不足以支撑 W9 开工**。理由见 §1.3。

### 1.2 为什么必须先插 W8.6

因为本轮暴露的核心问题**不是"输出被截断"，而是"失败被归错了因"**。如果带着错误的归因进 W9，你会朝错误的方向优化。

### 1.3 对你三个修法选项的评价

| 选项 | 评价 |
|---|---|
| **① 提高 max_tokens** | **可做，但只是止血。** 三点保留：中转是否遵守该参数未知；32,000 也可能是**模型侧最大输出**（须实测确认）；即便提到 64k，**只是把悬崖往后挪**，题更大时照样撞上 |
| **② ir-container-v1 分片声明** | **正解。** 而且它不是新发明——**你自己的 T2 三步协议和 T3.5 `expand-select.ts` 就是分片**。你为了逃离 T3 的"不读题面"而切到 T1，等于切到了**输出预算最饥渴的那一档**。②的本质是：**拿回一个有界输出、仍然诚实的协议** |
| **③ 压缩协议教学段** | **打错靶了。** 教学段是**输入**；plan 的输入只有 1346 tokens，输入根本不是瓶颈。本次 in:out ≈ **1 : 8.6**。压缩输入不会减少一个字节的输出 |

**并补两条你未列的（这两条比 ①②③ 更根本）：**

| 选项 | 为什么必须做 |
|---|---|
| **④ 让"截断"成为一类可识别的失败** | 见 §1.4。这是防止本轮问题**复发**的唯一办法 |
| **⑤ 路由到"无契约的方法族"必须零 token 拒绝** | 见 §1.5。这是本轮 75k tokens 被烧掉的**直接原因** |

### 1.4 核心诊断：**你刚刚暴露的是「假红」**

你已经修掉了「假绿」——T3 的 14/14 是一个永远不会失败的指标，让项目显得有能力而其实没有。

**本轮暴露的是它的镜像：假红——一次由 harness / 传输侧限制造成的失败，被归因给了模型。**

证据链：

| 事实 | 后果 |
|---|---|
| 输出撞到 32,000 上限而截断 | 截断是**提供方/传输层事实**（OpenAI 兼容协议会返回 `finish_reason: "length"`），**不是模型的协议违规** |
| 引擎却判为 `parse_failed`（**NONE** 类）→ 再判 `schema_violation`（**DRIFT** 类） | 把"输出预算不足"记成了"模型不合规" |
| 指导文案输出"**重试一次**" | 重试**必然同样失败**——因为上限没变 |
| 尝试 #1 与 #3 各烧 32,000，合计 **64,000 / 75,669 ≈ 85%** 的输出 | 85% 的预算花在一个**第一次陷入失败就已可知无法获胜**的重试上 |

**「假绿」与「假红」是同一种病**：**失败（或成功）信号不指向真实原因。**

- 假绿让项目**过度自信**（于是不做真实验证）；
- 假红让项目**朝错误方向优化**（以为"模型不会建模"，于是去调提示词；真相是"协议长度与输出预算不匹配"，需要对协议**重新架构**）。

**这就是为什么 W8.6 必须排在 W9 之前：归因错误会让你把 W9 花在提示词上。**

### 1.5 因果链复原：75k tokens 是怎么被烧掉的

```
预注册把 2024-C 标为 F3            ← 我的错误（见 §2 F 组）
        ↓
F2 优化契约不存在（只建了 F3/F4）
        ↓
路由器判为 F4（词频 F4×5 vs F3×2）  ← 路由误差
        ↓
F4 契约存在 → 不触发"零 token 拒绝"  ← 缺失守卫（选项⑤）
        ↓
用错契约 → 模型无合适候选集
        ↓
单次整体声明 ir-container-v1 → 输出膨胀
        ↓
撞 32,000 上限 → 截断 → parse_failed
        ↓
误判为模型违规 → 重试 → 再撞 → 再重试 → 耗尽
        ↓
BLOCKED，18 分钟，75,669 output tokens，0 产物
```

**关键点：如果路由器判对为 F2，引擎就会因"无 F2 契约"而零 token 拒绝——那个拒绝是正确行为。所以是路由误差把一个正确的拒绝变成了一次昂贵的失败。**

## §2 W8.6 任务条例

> **本轮定位：只修"让信号说真话"与"让指标可机械追踪"，不新增任何建模能力。**
> 编号：`W8.6-<组><序>`。每条含 **要求 / 验收证据 / 禁止**。
> 组：`A` 语义修复　`B` 预算修复　`C` 守卫　`D` 诊断保留　`E` 指标卫生　`F` 真值标签

### §2.1 A 组 —— 语义修复

**W8.6-A1　截断成为独立失败类**
- **要求**：新增 `truncated` 失败类（与 `parse_failed` / `schema_violation` 并列），**不得**把撞上限的输出归入 `parse_failed`。
- **验收证据**：构造一个必被截断的输入 → 失败类为 `truncated`，且不被归为 NONE/DRIFT。
- **禁止**：把截断归入 `parse_failed`（NONE）或 `schema_violation`（DRIFT）——**这二者会把传输限制记成模型违规**。

**W8.6-A2　`finish_reason` 贯通到失败分类**
- **要求**：从提供方响应中读取 `finish_reason`（或等价字段），并在分类时使用它。若该字段缺失，**记为"不可知"而非假定正常**。
- **验收证据**：一次真实运行的归档中可见 `finish_reason` 值；分类逻辑引用它的代码位置。
- **禁止**：在字段缺失时假定输出完整（那会重演本轮的错误归因）。

**W8.6-A3　截断的指导文案更正**
- **要求**：截断类失败的 humanized 文案**不得**输出"重试一次"；应指向"输出预算/协议长度不匹配"。
- **验收证据**：文案表 + 一条针对它的测试。
- **禁止**：让用户被指向一个**必然失败**的动作（本轮实测：重试两次、两次同样截断）。

**W8.6-A4　同因重试熔断**
- **要求**：同一节点内，若连续两次失败为**同一失败类且同一原因**，第三次不得原样重试——须中止该节点并如实记账。
- **验收证据**：一条测试：连续两次同因失败 → 不发起第三次。
- **禁止**：以"节点有 3 次 attempt 预算"为由把已知无效的重试跑满（本轮为此付出 32,000 output tokens）。

### §2.2 B 组 —— 预算修复

**W8.6-B1　显式声明输出预算**
- **要求**：请求体显式设置 `max_tokens`，取值来自**可配置字段**（不得硬编码）。
- **验收证据**：`real-provider.ts` 请求体含该参数；一次真实运行归档显示其生效。
- **禁止**：在未实测确认前假定中转/模型会遵守该参数。

**W8.6-B2　实测并记录提供方真实上限**
- **要求**：做一次探针，测出**当前路由下实际生效的输出上限**（是否 32,000、是否可提高、提高后是否被遵守），记录为事实。
- **验收证据**：探针记录（请求参数 → 实际返回长度 → `finish_reason`）。
- **禁止**：把"中介默认值"当作**不可变事实**写进结论而不实测（本轮 D8 观察 1 的表述偏绝对）。

**W8.6-B3　输入:输出比监控**
- **要求**：指标层记录每次运行的 in/out 比；当 out/in 超过阈值时显式标记。
- **验收证据**：新一轮快照含该比值；本轮基线 = **8.6 : 1**。
- **理由**：本轮的比值本身就是异常信号，但**没有任何指标捕捉到它**。

### §2.3 C 组 —— 守卫

**W8.6-C1　无契约即成拒绝**
- **要求**：若路由判定的方法族**没有已实现契约**，运行必须在**零模型调用**下拒绝，并给出可读原因。
- **验收证据**：一条测试：路由到无契约族 → `usage = 0/0` 且终态为明确的拒绝。
- **禁止**：路由到无契约族后继续调用模型（本轮因此烧掉 75,669 output tokens）。
- **本条是 §1.5 因果链的直接切断点。**

**W8.6-C2　路由与预注册不一致时的显式标记**
- **要求**：对 bench 内的题，若路由器判定 ≠ 预注册标签，**必须在报告中显式标出不一致**（不自动纠正，只标记）。
- **验收证据**：本轮 2024-C（预注册 F3 / 路由 F4）触发该标记。
- **禁止**：让不一致静默通过。

### §2.4 D 组 —— 诊断保留

**W8.6-D1　保留被拒容器的有界摘录**
- **要求**：`ir_producer` 拒绝容器时，保留**有界摘录**（头尾各 N 字符）或内容哈希 + 拒绝路径，落盘可查。
- **验收证据**：本轮 exec#2 若重跑，其 schema 违规的**具体字段路径**可被读到。
- **禁止**：只记 `refused 3 times` 而不记原因路径——**那使任何协议失败永久不可诊断**（本轮 exec#2 已不可知）。
- **依据**：仓库原则"模型可见 ⟺ 已记录"。

**W8.6-D2　BLOCKED 报告携带 usage**
- **要求**：BLOCKED 路径的 `run-report.json` **必须**含 `usage`（当前只在 DELIVERED 路径有）。
- **验收证据**：BLOCKED 报告含 usage；指标计算**不再需要人工从日志复算**。
- **禁止**：让指标依赖手工算术（本轮 8,785/75,669 由人工减法得出）。

### §2.5 E 组 —— 指标卫生

**W8.6-E1　`provider_mode` 字段**
- **要求**：每条指标记录新增 `provider_mode: "real" | "fake"`。
- **验收证据**：快照中 2024-A/B/C 标 `fake`，2024-C-real 标 `real`；跨模式汇总被机械禁止。
- **禁止**：让 fake 与 real 在同一数据结构里无法区分（当前状态即如此，与红线 N2 冲突）。

**W8.6-E2　`routed_family` 字段**
- **要求**：每条记录同时保留 `family`（人工真值）与 `routed_family`（路由器判定）。
- **验收证据**：2024-C 记录中二者不同（F2/F3 真值 vs F4 路由）。
- **禁止**：只存其一——那样**路由准确率无法长期追踪**。

**W8.6-E3　M2 交付条件化**
- **要求**：无交付物时 `m2_silent_errors` 记为 `null`（或显式 `N/A`），**不得记 0**。
- **验收证据**：2024-C-real 的 M2 不再是 0。
- **禁止**：让"没有交付"在数据上表现为"零错误"。

### §2.6 F 组 —— 真值标签（含我的错误撤回）

**W8.6-F1　人工标注真值方法族**
- **要求**：bench 内每道题的**真值方法族由人工标注**（允许标注为混合，如"F3+F2"），路由器对着它度量。
- **验收证据**：`bench/MANIFEST.json` 或单独真值文件含人工标签 + 标注人与日期。
- **禁止**：把路由器自己的输出当作真值（那是自证，与 T3 同类错误）。
- **依据**：这正是你主张的"不放权"原则——真值必须由你定。

**W8.6-F2　撤回我的预注册错误**
- **事实**：`DPH-方法族映射与核验表.md` 中我把 2024-C 归入 F3（数据驱动/统计）。**这是错的。** 2024-C「农作物的种植策略」核心是**带约束的多年种植方案优化**，主族应为 **F2**，F3（预测销量/价格/产量）是支撑。
- **要求**：在预注册文件中**追加修订说明**（不改冻结正文）：2024-C 真值 = `F3+F2 混合，优化为主`。
- **验收证据**：修订说明入档。
- **认领**：预注册标签、路由判定、真实构成三者**互不相同**（F3 / F4 / F2），而**最先错的是我**。

**W8.6-F3　F2 契约缺口登记**

- **验收证据**：缺口登记条目 + 范围定义。
