**信封/预算层**，没有一次是"模型建模不行"或"门禁过严"。

| 轮次 | 结果 | 直接原因 |
|---|---|---|
| 1 | BLOCKED | E2 撞提供方输出上限被截断（当时未设 `max_tokens`，中转默认值） |

## 二、修掉的四类缺陷（都由这次实测暴露）

1. **容器信封噪声**（两次尝试的形态都抓到）
   - attempt 1：容器**完整**、末尾多一个 `}`（`Extra data: line 1 column 14170`）
   - attempt 2：容器**完整**、后面跟一段写给自己的批注（`Note: claim criticality must be …`）
   - 修法：取第一个**完整**顶层对象（逐字符扫描、跟踪字符串与转义），丢掉尾随文本；
     唯一边界是尾随文本里不得再出现容器标记（可能是第二个修正版，仍拒绝）。内容检查未放宽。
2. **传输截断不兜底**：E2 撞输出上限 → 直接 `failed`，fail-soft 下也交付零内容。
   修法：截断分支先走 E1 直通兜底（标注交付），兜底不适用才终结；零重试不变。
3. **E1 自带 markdown 标题泄漏成论文章节**：模型的工作笔记有 `# B题 建模工作笔记`
   `## 总体思路`，注入正文后逐问章序号错位。修法：注入前降级为加粗行。
4. **兜底稿用机器占位符** `_(模型待写入)_`：Word 导出的 `no_placeholders` 门因此拒绝
   导出（6 处），PDF 里也是六段机器占位。修法：每个未产出的章写一句如实说明
   （这一章由谁产出、为什么没有、读者该注意什么）。

教学同步：容器标记必须是**同一个对象的第一个键**（不许写成独立对象/独立行）。

## 三、实测事实（对"为什么没走到产线链"的诚实归因）

- **模型把推理写进 content 通道**：E2 的输出 184,351 字符里绝大多数是
  "Let me carefully work through this task. I need to produce ONE JSON object…"。
  中转的 `max_tokens` 上限是 **65,536**（W8.10 探针已实测），装不下这种体量。
  `reasoning_effort: none` 对这个模型似乎不生效（它本来就不是独立 reasoning 通道的形态）。
- **E1 长度方差极大**：同一提示、同一环境，三次分别是 3,452 / 3,955 / 137,966 字符。
- **中转不稳**：第 4 轮前四次尝试里两次 `EMPTY_STREAM`、两次 `FINISH_REASON_UNKNOWN`。
- **教学是生效的**：模型在真实 E1 里按新要求写了短章标题
  （`[[REQUIREMENT: R-Q1]] 问题1：二项假设检验定最小样本量`），逐问章标题因此是
  「问题1：二项假设检验定最小样本量」这种题名，而不是题干切片。

## 四、下一步的选项（都需要用户裁决）

| 选项 | 说明 | 代价 |
|---|---|---|
| A. 换模型/路由 | 当前模型把推理写进正文，装不进 64K；换一个不在正文里推理的模型最直接 | 需要另一个 key/路由 |
| B. 走协议分片（`disableE1E2` + shard-declare） | 三次小声明代替一次大容器（本就是为这种中转设计的），每片远低于上限；代价：失去 E1 通道，B3/B4 保真检查的前提变化 | 代码改动中等 + 一次真实运行 |
| C. 加输出长度守卫 + 针对性纠正 | 超过 N 字符仍未出现完整对象就提前中断该次调用，并按"你在正文里推理了"给出纠正；省下剩余预算，但模型可能继续这样写 | 代码改动小 + 可能多轮 |
| D. 接受当前 `B-e1-direct` 形态 | 兜底稿已无机器占位、结构对齐参照物、每章有如实说明；但它只是"素材"，不是产线链论文 | 零成本 |
