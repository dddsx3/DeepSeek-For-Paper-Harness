## §3 待收口项目：E2E 真实验证

> **状态：`待收口`（PENDING）**
> **阻塞原因**：当前环境无真实 API key。
> **收口触发**：用户补齐真实 API key。
> **本节的用途**：让下次补齐 key 时**不必重新推导该做什么**，且**不重演 W8.5 的 75k token 浪费**。

### §3.1 为什么现在不能做

- 所有标 `阻塞` 的项最终都要靠真实模型调用暴露。
- 但**直接补 key 就跑，会重复 W8.5 的浪费**：那次正因为缺前置守卫，一次 18 分钟/75,669 tokens 的运行换来零产物。

### §3.2 前置条件（**必须先清，再花 key**）

| # | 前置条件 | 对应问题 | 为什么必须前置 |
|---|---|---|---|
| **P1** | B2 探针重跑并 dump raw SSE，结清 reasoning-channel 假设 | O-L1-01 | **它决定 W9 的分片片长**。用未验证的推断去切片，片会切错；若真相是中转吞 content，分片完全无效 |
| **P2** | 分片声明协议落地 | O-L1-03 | 不分片就必然再撞输出预算，等于重跑 W8.5 |
| **P3** | 路由器与真值对齐（或改为契约存在性优先） | O-L1-04 | 路由错 → 用错契约 → 输出膨胀 → 撞上限。这是 W8.5 浪费的**最上游**成因 |
| **P4** | per-run 预算门落地 | O-L5-03 | **没有它，真实 key 会被无上限烧**。W8.5 单 run 75,669 output tokens 无任何上限 |
| **P5** | 把"可跑题"判定写入 bench 文档 | O-M-05 | 已契约族 = F3/F4 → **只有 2024-B 可直接跑**。不写下来，下一个执行者可能又选 C 题 |

**P2 与 P3 是 W9 的主体工作；P1 是 30 分钟的小事且必须在 P2 之前；P4 是保护 key 的保险。**

### §3.3 收口清单（补齐 key 后要验的项）

| # | 验证项 | 判定标准 | 对应 MVP |
|---|---|---|---|
| **V1** | **2024-B 真实运行**（唯一路由 × 契约对齐的题） | 产出非空交付（`CLEAN` 或 `MARKED`） | **MVP-1** |
| **V2** | 2024-B 同题重跑 ×3 | ≥2/3 交付（证明不是运气） | **MVP-2** |
| **V3** | 全程零人工介入 | `m3a` 有真实样本且为 true | **MVP-3** |
| **V4** | `MARKED` 附录首次实测 | 附录实际内容被完整归档（W8.5 因 BLOCKED 未能检验） | — |
| **V5** | 下游链路首次被真实内容跑过 | 骨架 10 章节 + 符号表/假设表由真实 IR 生成；结论数字守卫生效；V1–V4 在真实 IR 上的误报数被记录 | — |
| **V6** | M1 首次非假读数 | `metrics-snapshot` 中 M1 有一行 `true` | **MVP-1** |
| **V7** | 分片协议后的 2024-C（若 F2 已落地） | 同 V1 标准 | 覆盖 C/E 类 |
| **V8** | M3c 真实值 | 配 pricing 后 `m3c_cost_usd` 非 null，且 per-run 预算门可触发生效 | **MVP-5** |

### §3.4 收口的退出判据

**E2E 收口 = 达成**，当且仅当：

1. V1、V2、V3 **全部达成**（即 **MVP-1 / MVP-2 / MVP-3 达成**）
2. V4、V5 有完整归档（不要求达成为好结果，要求**被真实内容检验过**）
3. 失败结果同样原样归档（沿用 W8.5-D8 纪律）

**明确不在收口范围**：MVP-4（图形层）、MVP-5 的完整实现（V8 只验"可见 + 可触发"）。**收口的目标是证明"能出稿"，不是证明"稿子好"。**

### §3.5 恢复验证时的一次性动作清单

```
1. 确认 HEAD 与前置条件 P1–P5 全部完成
2. provider 冒烟：确认实际服务模型名（记录，不假定）
   —— 已知：y-api 行为已变，v4-flash 不再被映射到 hy3
3. 确认 per-run 预算门已启用并设上限
4. 命令行（基线参考）：
   npx tsx apps/paper-shell/src/cli.ts run bench/problems/2024-B/problem.pdf \
     --mode strict --fail-soft --out bench/results/2024-B-real
   —— 注意：2024-B 有附件吗？若无附件需确认题面直读路径
5. 归档：run-report（含 usage）、交付物全文、附录、metrics-snapshot 增量
6. 失败则执行 D8：失败码 + 失败层 + 原始错误 + 逐次尝试链
```

```

      │
      ├─ 需先清 P1（SSE 结清）── 决定 ──► P2（分片协议）

                    │

            E2E 收口（§3.3 V1–V8）
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
   MVP-1/2/3    V4/V5 下游     MVP-4/5
```

## §5 明确不混入收口的东西

| 项 | 为什么不混入 |
|---|---|
| 图形层（O-L1-09 / MVP-4） | 是独立工作块；收口的目标是"能出稿"，不是"稿子好看"。混入会拖长收口且掩盖 MVP-1 的真实状态 |
| F1 契约（O-L1-06） | 覆盖 A/D 类所需；与"首次交付"无直接关系 |
| skills 内容库（O-L5-04） | 高价值但后置 |
