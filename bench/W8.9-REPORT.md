## §2 各项实现与证据

### 2.1 A1 —— 代码来源与新鲜度守卫

**机制**：`checkCodeProvenance()` 断言 `mtime(包入口 lib/index.js) >= mtime(该包 src 下最新 .ts)`，不满足则**拒绝启动真实运行**（`--fake`/`--replay` 仅警告），退出码 4。

**为什么是 mtime 而非哈希**：源码→lib 不是逐文件映射（tsdown 打包成单文件），哈希方案需要一个构建时写入的清单文件，那会把守卫绑定到构建流程本身——**而守卫必须在构建被跳过时也能工作**。判据的诚实边界写在模块头注释里：mtime 不能证明内容语义一致，它证明的是"没有发生'改了 src 却没重建'这一具体事故"。

**变异击杀证明（纪律 14）**：

```
① 合格：ok = true   "entry lib/index.js is 98498 ms newer than the newest source"
② 变异：touch src/delivery/execution-gate.ts
   → ok = false  "entry lib/index.js is 19330441 ms OLDER than the newest source — the built entry is stale"
③ 还原：ok = true   （同 ①）
```

**真实运行中的见证**：三次运行均打印 `[CODE-FRESH] 代码来源已断言：entry lib/index.js is N ms newer than the newest source`。

### 2.2 A2 —— `route_mismatch` 改为组件集合比较

**根因（实测）**：真值标签允许混合族（`TRUTH-FAMILIES.json` 的 `"F3+F4"`），路由器的 `family` 是单个主族（`"F4"`）。朴素 `truth !== routed` 把**每一个合法混合族题**标成 mismatch——2024-B 因此与 `RUNNABLE-PROBLEMS.md` 的"一致"结论直接矛盾（**假红**，使路由准确率度量失效）。

**修法**：`routeCoversTruth(truthLabel, verdict)` = 真值的每个组件都出现在路由器的组件集合里（子集关系）。主族不参与判定——它只是"命中分最高者"（供契约 banner），不是"题目只需要这一族"的主张。

**实测**：2024-B 路由 `F4×4 + F3×3`；`routeMismatch("F3+F4") = false`（此前 = `true`）。三次真实运行均为 `False`。

### 2.3 A3 —— 空流独立成类

**事故形态（W8.8 run#3/#4）**：HTTP 200 + 空 SSE，曾落在 `FINISH_REASON_UNKNOWN`，与"协议真有问题"不可区分（假红的相邻形态）。

**修法**：把 finish 判定抽为纯函数 `classifyStream({inBandError, finishReason, contentChunks, sawAnyChoice})`，优先级固定且完备：`in-band error > length > EMPTY_STREAM > unknown > stop`。`EMPTY_STREAM` 的两种形态（`no choices at all` / `choices present, all deltas empty`）在消息里**可区分**。

**顺带修掉一个既有真实缺陷**（本批测试发现）：`sseLines` 的尾部处理只 flush 了解码器余量、**从不检查 `buffer` 残留**——流在无换行符时关闭会**丢掉最后一行 `data:`**。若那行携带 `finish_reason`，正常的 stop 会被误判成 `FINISH_REASON_UNKNOWN`——**正是本轮要消除的误分类**。修法：尾部 = `buffer + decoder.decode()`。

### 2.4 A4 —— 分片成为默认路径

**判据来源**：W8.6 的教训是"未验证的协议改动不得直接改默认"。该教训在**证据侧**已满足：分片路径有自己的测试面，而单次路径是**已知会撞输出上限**的那条（W8.5 烧掉 75,669 output tokens；W8.8 run#3/#4 空流）。**继续把已知失败的路径当默认，才是现在的风险。**

**修法**：`shardDeclareEnabled()` 单一读取点，优先级 `disableShardDeclare` > `shardDeclare` > 默认 `true`。开关**被反转而非删除**：`disableShardDeclare: true` 恢复单次声明（A/B 与回归）。

**测试抓到一处真实接线缺口**：`executor-service.ts` 从未透传 `disableShardDeclare`——"关闭"实际表现为"默认开"。已修（schema + 透传 + 类型三处）。

### 2.5 B1/B2 —— E1/E2 拆分与零数字通道

**E1**：`e1AnalysisInstruction(requiredOutputIds)` —— prose/Markdown，**不提 JSON、不提容器、不提 schema**（禁项：不得用"加强协议教学"逼 E1 产 JSON）。

**E2**：`e2NormalizationPrompt(e1Text, containerTeaching)` —— 输入是 **E1 全文**；职责是映射，不是创作；携带 `e1_span` 的忠实义务与零数字规则。

**B5（E1 只跑一次）**：`#e1ByRun` 缓存；重试复用并落 `E1Reused` 审计事件。**真实运行见证**：run-3 的审计轨迹中 `E1Analysis` 出现 1 次、`E1Reused` 出现 2 次，E1 文本始终 3388 字符——**E2 三次尝试归一化的是同一份分析**（可复现性未被破坏）。

**IR 改动（B3 的必需前提）**：`AssumptionSpec`/`EquationSpec` 新增可选字段 `e1_span`。**这不是可选的**：`.strict()` 使未知键成为硬拒绝——本批测试第一次跑就撞上（`schema_violation`）。这正是 Q 支线 `CAPABILITY-SCHEMA.md` 预测的接缝。

### 2.6 B3/B4 —— 保真双向锚定与逐问覆盖

四条规则，每条都有构造性反例：

| 规则 | 抓什么 | 反例 |
|---|---|---|
| **B3 正向**（声明须逐字锚定 E1） | 改写冒充引用 |  paraphrase → `e1_span 在 E1 中找不到逐字匹配` |
| | 无锚点 | 缺 `e1_span` → `未声明 e1_span` |
| | 过短（偶合） | `采用`（2 字）→ `e1_span 过短` |
| **B3 反向**（E1 假设须被声明） | E1 标了但 IR 没声明 | 检出 `A-SEQ` |
| **B3 锚点同一性**（声明须有同名锚点） | **凭空造假设**（借用别处的真 span） | 检出 `A-INVENTED` |
| **B4 逐问覆盖** | E1 漏答一问 | 检出 `R-OUT-2` |

> **"锚点同一性"是本批自查发现的缺口**：只查"有 span 且 span 存在"是不够的——E2 可以凭空造一条假设，再把 E1 里**另一条**假设的句子拿来当自己的 span。那样的声明在正向与反向两条检查下**都会通过**。这条检查把"声明 ↔ 锚点"按 **id** 对上，才是 H6 说的"凭空造假设"的机械落点。

**设计意图（W8.9-B3 逐字）**：这是"识别优秀建模"的机械落点——harness 判断不了推理好不好，但可要求形式化忠实于推理。

### 2.7 C2 —— 局限写进交付物

`report-renderer.ts` 的交付尾注新增固定段落：已核验**结构完整 + 数字可溯源 + 形式化忠实**；**未**核验**实质正确性**（建模思路优劣、假设物理真伪、方法选择恰当性）。**禁止**把"结构完整 + 保真"表述为"建模质量已验证"（W8.9-C2 逐字）。
