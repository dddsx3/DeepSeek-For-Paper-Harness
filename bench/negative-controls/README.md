# M-Bench 负对照 — 作用域声明（W8.5-B4）

> **必须先读这一句**：本目录的负对照在**合成 fixture** 上运行。
> 它验证的是**指标函数对已知恶化的反应性**（"这个操作会不会让指标变红"），
> **不验证管线在真实输入下的行为**（真实运行的行为由 `bench/results/` 的真实运行归档回答）。

## 它证明什么

- `run-all.mjs` 的 7 组控制（18 项检查）对**指标函数**输入注入已知恶化：
  - NC-1：分层/禁汇总防护存在 + 混合会虚高
  - NC-2：复述稿的 n-gram 判定会翻负
  - NC-3：无源数字注入 → M2 静默错误升、M1 翻负
  - NC-4：人工介入 → M3a 翻负；未计价 → M3c 报 null（禁止假 $0）
  - NC-5：缺骨架 → M4 降、M1 翻负
  - NC-6：DataArtifact 拒绝保留 → M5 保持 0
  - NC-7：篡改 bench 文件 → 完整性校验红
- 每项 PASS 的意思是：**当指标函数收到那个已知恶化的输入时，输出确实变坏了**。指标是活的，不是恒绿的。

## 它不证明什么（后续报告禁止的表述）

- ❌ 不证明"管线已验证"——管线在真实输入下的行为只有真实运行能回答。
- ❌ 不证明"引擎可靠"——fixture 是构造的，不是赛题。
- ❌ 不替代留出集运行（W12）——预注册与逐题报告才是交付率的证据。

## 与真实测量的关系

| 手段 | 回答的问题 |
|---|---|
| 负对照（本目录） | 指标函数会不会动？ |
| 真实运行归档（`bench/results/`） | 真实输入下发生了什么？ |
| 预注册 + 逐题报告（W12） | 交付率是多少、哪族虚高？ |

三者不可互相替代。"18/18 全绿"只说明第一行。
