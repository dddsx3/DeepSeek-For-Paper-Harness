# LIMITS-TEMPLATE.md（Q1-B5）

> **产物编号**：Q1-B5　**要求**（§3.2-B5）：把 Q1-A4 的类别写成**可填充句式**。验收证据：模板 + **在 DPH 交付物附录中的引用位置**。
> **出处**：`[P-11]` + `[Q-06]`。
> **纪律**（N6）：**禁止写成免责声明**。每条边界必须**可被检查"是否声明了"**——即每个槽位都必须**非空可判定**（是数值、是闭集成员、是引用，而非形容词）。

---

## 0. 使用说明（三句话）

1. **本模板是必填表，不是可选附录。** 每个 `{{槽位}}` 填不上，说明该边界**未被量化**——此时**不得**填"不适用"，而应填 `UNQUANTIFIED` 并在 `{{未量化原因}}` 中说明，使其**成为一条可见的缺口**而非一句套话。
2. **每条声明对应一个 `BoundaryDeclaration` IR 对象**（见 §3），由 `renderDeliveryAppendix` 从对象生成文本。**文本是对象的投影，不是对象的来源。**
3. **填不出数值的边界，不许写成句子。** 这是与免责声明的分界线。

## 1. 边界声明表（四类，逐类给句式）

### L-1　同源复核风险

```markdown
### L-1 复核独立性边界

本复核通道与生成通道共享：**{{共享环节}}**。
若该环节出错，本复核**不能发现**——这是本复核的天花板。

独立性仅在以下维度上成立：**{{独立维度}}**
（取值必须 ∈ {不同模型, 不同输入形态, 不同工具, 不同数据视图}；可多选）

**独立性的证明方式**：{{证明方式}}
（必须说明如何验证"该维度确实独立"——如：两通道的模型 ID 不同且已在
ExecutionRecord 中记录；或两通道读取的输入 DataArtifact 的 content_hash 不同）

**共享环节出错的检出手段**：{{检出手段}}
（**必填**。仅声明"共享 X 故不能发现 X 类错误"是自认无能；必须给出
一个不经过该环节的补偿校验，并说明其覆盖范围。）

该手段**覆盖**：{{覆盖范围}}
该手段**不覆盖**：{{不覆盖范围}}
（两者都必须非空。"全覆盖"不可能，"无覆盖"是免责声明。）
```

**填充示例**（材料侧 `[P-11][0]` + `[F-08]` 的形态）：

| 槽位 | 材料侧可填的值 |
|---|---|
| `{{共享环节}}` | Vision OCR 文本（题面与附件的唯一输入通道） |
| `{{独立维度}}` | （材料侧**为空**——这正是 `[P-11][0]` 承认的缺陷） |
| `{{证明方式}}` | （材料侧**为空**） |
| `{{检出手段}}` | 数字池 vs 正文小数全量溯源扫描（`_tmp/data_check_scan.py` + `_numpool.pkl` 12,008,820 B） |
| `{{覆盖范围}}` | OCR 原文中的数字是否全部登记到 facts（实测告警：**53 个数字未登记**） |
| `{{不覆盖范围}}` | （材料侧**为空**——`AUDIT_REPORT.md` 未给扫描口径、容差与分母，**手段存在但不可复算**） |

> **材料侧的这条声明是"诚实的"，但不是"合格的"**——它诚实承认了共享（L-1），**但 L-1b 的三个槽位中，`{{独立维度}}`/`{{证明方式}}` 为空、`{{不覆盖范围}}` 为空**。按本模板，该条应填 `UNQUANTIFIED` 并标注"无独立维度 ⇒ 复核力为零；检出手段口径不可复算 ⇒ 补偿力未知"。**这就是本模板与免责声明的分界：模板强迫承认这些空白，而免责声明会让这句话听起来像一种谦虚。**
>
> **材料侧最有力的证据是它自己的报告**：`[F-08]` 逐字警告"OCR 原文中有 53 个数字未登记到 facts（可能漏抄）"——**这正是 L-1 所担心的"共享环节出错"的实例**（OCR 阶段的可疑活动），而它**恰好由 L-1b 的检出手段发现**。**故 L-1b 不是理论要求，它已经在材料侧产生了实际价值**——只是其口径未被记录，故不可复算。

### L-2　无实测数据

```markdown
### L-2 无实测数据边界

对象：**{{对象}}** 无任何独立观测。
本研究的正确性主张**限于**以下自证手段：

| 手段 | 具体结果 | 位置 |
|---|---|---|
| {{自证手段 1}} | {{数值}} | {{位置}} |
| {{自证手段 2}} | {{数值}} | {{位置}} |
| {{自证手段 3}} | {{数值}} | {{位置}} |

**本文不主张**与实测的吻合，不报告 R²/拟合精度/误差百分比。
```

**填充示例**（材料侧 `P-11[2]` + `PX-C1` 的形态）：

| 槽位 | 值 |
|---|---|
| `{{对象}}` | 药材内部 T(r,t) / C(r,t) |
| `{{自证手段 1}}` | 解析解（Bessel + Duhamel）最大偏差 \| `2.9459e-4 ℃`（dt=0.25）/ `1.1945e-3 ℃`（dt=1.0） |
| `{{自证手段 2}}` | 两层守恒残差 \| 离散 `0.0000%`（格式自证）+ 物理自洽 `2.22%` |
| `{{自证手段 3}}` | 网格与时间步无关性 \| `N200→400` 差 `1.08e-5`；`t*` 相对变化 `<1%` |

> **机械检查**：`{{自证手段 n}}` 的**行数 ≥ 3**（材料侧实测为 3 项，且 `PX-C1` 的 `falsifiable_check` 逐字要求"必须**同时**含解析解偏差、两层守恒残差、网格与时间步无关性数据**三项具体数字**"）；每个 `{{数值}}` 必须是**数字**（正则 `\d` 命中）；全文对 `{{对象}}` 的禁用语（`与实测吻合` / `验证.*实测` / `R\^2` / `拟合精度`）命中数 = **0**。
>
> **⚠️ 假绿风险**：禁用语检索**只能证明"没出现禁用语"**，不能证明"没有等价的越界主张"（如"结果与文献值一致"）。故本条的检查须标注**覆盖范围**（"覆盖 4 个正则模式，非穷尽"）——这是 M7（防误报）的双向克制。

## 2. 交付物中的组装形态

### 2.1 在 DPH 交付物附录中的引用位置（**实测**）

| 位置 | 文件 | 挂载方式 |
|---|---|---|
| **`MARKED` 附录** | `packages/paper/paper-foundation/src/delivery/delivery-grade.ts` :: `renderDeliveryAppendix(grade, annotations)` | 已实现，生成 `## 附录：交付标注（自动生成）` 表格（`| # | 检查项 | 位置 | 原因 |`）。**本模板的 L-1 / L-1b / L-2 / L-3 / L-4 应作为该附录的一个后续小节**（或并列节），因其同为"未通过/需声明的项" |
| **审计事件** | `src/executor.ts:640-729` 的 `delivery_graded` 审计条目 | 边界声明应随 `GradeAnnotation` 一起进入审计（使"声明了什么"成为**可追溯记录**） |
| **论文正文** | `AssumptionSpec` 对应的假设节（`ir/contract-objects.ts:64-83`） | L-3/L-4 的 `{{来源}}` / `{{假设_ref}}` 指向既有 `AssumptionSpec`；正文渲染时**从对象生成** |
| **复核报告** | `verification/v5-adversarial.ts` 的 findings 之后 | L-1 的独立性声明应与 V5 的对抗发现**相邻**（复核的边界紧邻复核的结果） |

> **关键**：`renderDeliveryAppendix` 对 `CLEAN` 返回 `''`（空串）——即**无标注则无附录**。若边界声明挂在同一通路，则 `CLEAN` 的交付**不会有边界附录**——**这是错的**：L-2（无实测数据）与 L-3（参数不可验证）在**任何**真实交付中都成立，与 grade 无关。
>
> **故本模板的实施要求**：**边界声明必须与 `MARKED` 附录分离**——前者是**无条件生成**的（每个交付都有局限），后者是**条件生成**的（仅有未通过项时）。这一区分须在 Q1-D1 中明确。

## 3. 建议的 IR 对象（供 Q1-D1 采纳）

```ts
/**
 * BoundaryDeclaration — Q1-B5 (DPH-Q 支线规格, 未实施).
 *
 * 使"是否声明了边界"成为可机械检查的对象。关键设计: 每个槽位
 * (slot) 必须携带**可判定值**, 而非自由文本 —— 否则退回免责声明。
 */
export const BOUNDARY_CLASSES = ['L-1', 'L-1b', 'L-2', 'L-3', 'L-4'] as const

export const boundaryDeclarationSchema = zod
  .object({
    declaration_id: idSchema,
    boundary_class: zod.enum(BOUNDARY_CLASSES),
    /** 被边界约束的对象: AssumptionSpec / DataArtifact / Result 的引用。 */
    subject_ref: refSchema,
    /** 共享环节(L-1) / 对象(L-2) / 参数(L-3) / 假设(L-4)。 */
    object_text: textSchema,
    /** 槽位值: key -> 值。值必须是数字/引用/闭集成员, 由 class 决定 schema。 */
    slots: zod.array(
      zod.object({
        key: idSchema,
        /** 数值槽位。UNQUANTIFIED 时必须为 null 且 reason 非空。 */
        number_value: zod.number().nullable(),
        /** 引用槽位(指向 IR 对象)。 */
        ref_value: refSchema.nullable(),
        /** 闭集成员槽位(L-1 的独立维度)。 */
        enum_value: textSchema.nullable(),
        /** UNQUANTIFIED 的原因(使缺口可见)。 */
        unquantified_reason: textSchema.nullable(),
      }).strict(),
    ),
    /** 生成位置: 必须出现在交付物的哪个节。 */
    must_appear_in: refSchema,
  })
  .strict()
  .refine(
    v => v.slots.every(s =>
      s.number_value !== null || s.ref_value !== null || s.enum_value !== null ||
      (s.unquantified_reason !== null && s.unquantified_reason.length > 0)),
    { message: 'every slot must carry a decidable value OR a non-empty UNQUANTIFIED reason' },
  )
```

> **`.refine` 的那条规则是整个模板的机制核心**：一个槽位**要么有可判定值，要么有非空的"未量化原因"**——**没有第三条路**。这使"免责声明"在类型层就无法表达。
