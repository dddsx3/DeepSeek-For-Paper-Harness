# `judge` 分流的判定标准 + 存在性/实质分离（Q1-B2）

> **产物编号**：Q1-B2　**要求**（§3.2-B2）：① 给出"能力应归 `machine` 还是 `semantic`"的**判定标准**；② 用 23 条**逐条复核**（看是否有归类错误）；③ **另设"存在性 vs 实质性"标记**——采用 `[F-04]`（`[Q-15]`）的做法：纯交付能力只验存在，且必须**显式注明"不代表内容正确"**。
> **禁止**：用"感觉能机械化"作标准；把存在性验证混入实质验证而不标注。

## 1. 判定标准（三问，逐问闭集化）

> **禁止"感觉能机械化"**。下面三问的答案都必须是**可判定的对象**，不是印象。任一问为"否"即降级为 `semantic`——**默认降级**（宁可 semantic 也不假绿）。

### 问 1：断言的**观测对象**是否已在 IR 内存在？

| 判定 | 条件 |
|---|---|
| ✅ 是 | 存在 `subject_ref` 可指向的 IR 对象（`Result` / `RunArtifact` / `DataArtifact` / `EquationSpec` 的字段） |
| ❌ 否 | 观测对象是**自由文本**（论文段落、代码注释）、**代码结构**（赋值模式、分支形态）、或**尚不存在的产物** |

**理由**：DPH 的 `numeric_consistency` 门"walks every NUMERIC Claim; exact value + unit equality"——它**只能走 IR 内的对象**。IR 外的东西无法被任何既有门观测。

> **这条是主要的分流闸门**。材料侧实测：23 条中 8 条 `semantic`，其 `criterion` 全部落在"机制再现 / 归因分解 / 诚实表述 / 假设声明"这类**文本或结构**对象上。

### 问 2：断言的**判据**是否可归约为闭集算子？

`THRESHOLD_OPERATORS`（Q1-B1）是闭集：

| 算子 | 可表达 | 不可表达 |
|---|---|---|
| `LT/LE/GT/GE/EQ/NE` | 单点数值比较 | — |
| `ABS_LT/REL_LT` | 带容差的数值比较 | — |
| `MONOTONE_*` | 序列的单调性 | 非单调但有界的形态 |
| `MAX_OVER_AXIS` | "各处"类语义（max over r） | 空间分布的形状 |
| `COUNT_ZERO` | "命中数为 0"（正则检索类） | 命中数为 0 但**语义正确**的情形 |
| `MATCHES_EXACT` | 逐字/逐位相等 | — |

| 判定 | 条件 |
|---|---|
| ✅ 是 | 判据可写成上述算子之一（含多算子组合） |
| ❌ 否 | 判据需要**语义理解**（"是否再现了物理内涵"）、**结构判断**（"是否做了分段切换"）、或**开放性论证**（"归因是否合理"） |

> **注意**：`COUNT_ZERO`（正则检索）看似万能，但它是**弱机械**——它只能证伪"出现了禁用语"，不能证明"实质做了某事"。**故用 `COUNT_ZERO` 的条目必须配一条阳性断言**（"必须含…数字"），否则是假绿。材料侧的 `PX-C1` 正是这么做的（正则命中数=0 **且** 校核章节必须含三项具体数字）。

### 问 3：断言失败时，**是否必然指向实质错误**？

| 判定 | 条件 |
|---|---|
| ✅ 是 | 失败 ⇒ 一定是实质问题（如"偏差 > 阈值"⇒ 解不对） |
| ❌ 否 | 失败可能是**表述问题**（用词不同）、**组织问题**（放在别的小节）、**等价形式**（用别的方法做了同一件事） |

**理由**：这是**防误报**的要求（机制 M7：`[Q-11]` "未逐字匹配不等于虚构"）。**若失败可能是误报，则该条不得进 `machine`**——因为 `machine` 项的失败在 DPH 侧是**拒交付**（`CRITICAL_GATE_IDS` 的 FAIL 语义），误报的代价是硬阻塞。

> **三问的合取**：`machine` ⟺ 问1 ✅ ∧ 问2 ✅ ∧ 问3 ✅。**任一为否 → `semantic`**。

### 2.2 三条不一致的理由（**逐条**）

#### ❌ `P4-C1`：材料 `semantic` → 本支线 `machine`

| 问 | 复核 |
|---|---|
| 问 1 | ✅ **对象在 IR**。`R(t)` 是**外生给定**的输入（附件 2），已作为 `DataArtifact`（`role=INPUT_DATA`，带 `content_hash`）存在。断言对象是 `Result` 上的 `R(0)` / `R(21600 s)` / `R(259200 s)` 三个值与单调性 |
| 问 2 | ✅ **闭集算子**。三个 `ABS_LT`（容差 1e-5）+ 一个 `MONOTONE_NONINCREASING` + 末值 `< 0.0120` 的 `LT` |
| 问 3 | ✅ **失败⇒实质**。`R(21600 s) = 0.01374` 与 `R(259200 s) = 0.01198` 是**题面附件 2 的实测值**，插值错、域未收缩、或用固定 R，都会失败。**不存在"表述不同"导致失败的空间**——要么插值对，要么不对 |

> **材料为何标 semantic**：`criterion` 里含"**不得**由 `rho(C)` 反算 `R` 与 PDE 联立"这一**否定式**要求，看起来需要理解。但**否定式要求可以像 T-3 那样用探针转成阳性信号**（反算会在约 24 h 后给出负 `C`，这是可断言的数值信号——材料自己的 `falsifiable_check` 就写了这个数）。**否定式不是降级为 semantic 的充分理由。**

#### ❌ `P4-C4`：材料 `semantic` → 本支线 `machine`

| 问 | 复核 |
|---|---|
| 问 1 | ✅ 三个受控算例的 `t*` 都是 `Result` 对象（数值） |
| 问 2 | ✅ `COUNT`（存在 ≥3 个算例）+ 区间断言（B 段 `>120 h`、C 段 ∈[48,72] h）+ **符号相反**（两个贡献的差值符号） |
| 问 3 | ✅ 失败⇒实质。"只报最终 `t*` 而无分解"是**产物缺失**（可机械检测）；"两贡献同号"是**实质归因错误** |

> **材料为何标 semantic**：`criterion` 含"据此论证移动边界的必要性"——"论证"是人读词。但**论证的骨架（3 个算例 + 符号相反）完全可机械断言**。材料自己的 `falsifiable_check` 逐字写了"若只报最终 `t*` 而无分解、或分解后两贡献同号，判不成立并 raise"——**这就是 machine 的定义**。**`criterion` 的人读措辞不应决定 `judge`**；决定 `judge` 的是 `falsifiable_check` 的**可执行性**。

#### ❌ `PX-C1`：材料 `semantic` → 本支线 `machine`

| 问 | 复核 |
|---|---|
| 问 1 | ⚠️ **对象是论文文本**——但这是 `COUNT_ZERO` 算子的**标准适用域**（"全文正则检索命中数为 0"），而 `COUNT_ZERO` 在闭集内 |
| 问 2 | ✅ `COUNT_ZERO`（针对内部场的"与实测吻合"/"验证.*实测"/`R^2`/`拟合精度`）+ **阳性断言**（校核章节必须含解析解偏差、两层守恒残差、网格与步长无关性三项**具体数字**） |
| 问 3 | ✅ 失败⇒实质。正则命中 = 越界主张（**实质错误**，不是表述问题）；阳性断言缺失 = **校核未做**（实质） |

> **材料为何标 semantic**：涉及"诚实表述"这一语义范畴。但**该条的 `falsifiable_check` 是全 23 条中最机械的之一**（正则 + 计数 + 数字存在性）。**"诚实"是关于内容的规定，不是关于判定的方式**——规定"不得声称 X"完全可以机械执行。
>
> **⚠️ 但必须附一条限制**（否则是假绿）：`COUNT_ZERO` 只证明"没出现禁用语"，**不证明"没有等价的越界主张"**（如"模型结果与文献值一致"）。故该条**必须**与阳性断言成对使用，且**在 DPH 侧应标注为 `CUSTOM` 检查**（需专用脚本），并在交付时注明"本检查覆盖 4 个正则模式，非穷尽"。**这正是 M7（防误报）要求的克制。**

## 3. 拆条原则（本轮**只立规，不实施**）

> 复核中发现 **3 条**（`P1-C4` / `P3-C4` / `P4-C2`）的 `falsifiable_check` **混合了可机械与不可机械的部分**。它们的 `judge` 取值因此是"多数表决"的结果，而不是清晰的分流。

**原则**（供 Q1-D1 采纳）：

| # | 规则 |
|---|---|
| **R1** | **一条能力只承担一个判定通道**。混合的 `falsifiable_check` 必须**拆成多条能力**，每条 `judge` 单一 |
| **R2** | 拆出的 machine 条**继承**原 `source_anchor` 与 `required_output_ref`；semantic 条保留原 `criterion` 全文 |
| **R3** | 拆条后**总条数增加**，但 `verification_depth` 与 `boundary_refs` **不重复计算**（避免"不重复计量"的反面——材料 `[P-10][9]` 的教训） |
| **R4** | 拆条**必须记录映射**（原 id → 新 ids），使跨版本对账可行 |

> **不实施的理由**：拆条会改变材料侧 23 条的**结构**（H1 要求"23 条全字段提取完成"——已完成，见 `Q1-A1-capabilities.md`）。**本轮如实记录需要拆的 3 条，由主线在 W9 后决策是否实施**（§5.4）。

## 4. 存在性 / 实质性分离标记

### 4.1 标记定义

| 字段 | 闭集取值 | 语义 | 硬要求 |
|---|---|---|---|
| `verification_depth` | `EXISTENCE` | **只验证产物存在**（文件在、结构对、行数列数对）。**不代表内容正确** | 必须携带 `existence_disclaimer`（非空） |
| | `SUBSTANTIVE` | 验证内容正确性（数值、关系、机制） | `existence_disclaimer` 必须为 `null` |

`existence_disclaimer` 的**标准句式**（照抄 `[Q-15]` 的措辞，逐字）：

> 「本项仅验证交付存在，**不代表内容正确**。」

> **为什么必须字段化**：`[Q-15]` 的注记是**散文**（"仅验证交付存在，不代表内容正确"）——散文会被读者略过（N10 明确禁止把它读作"内容已验"）。字段化后，"哪些能力的验证是浅的"变成**可查询的集合**：`{c | c.verification_depth == 'EXISTENCE'}`。

### 4.2 材料侧实测的分离账（与 §0.5-D-2 对账）

| 事实 | 值 | 证据 |
|---|---|---|
| `[F-02]` 能力条数 | **23** | `[P-02]` 长度 |
| `[F-03]` 裁定条数 | **19** | `VERDICT` 键数实测 = 19 |
| 差集 | **4** = `P1-C6` / `P2-C4` / `P3-C5` / `P4-C5` | 实测 |
| 差集的特征（**三处重合**） | ① 恰为四问的"结果交付"能力；② 恰为 `machine_check == 'delivery'` 的 4 条；③ 恰为 `falsifiable_check` 为**空**的 4 条 | 实测交叉表 |

> **这是材料侧最干净的一处设计**：`judge=machine` 且 `machine_check=delivery` 且 `falsifiable_check` **为空**——**四个维度指向同一个 4 条集合**。说明作者是**有意**把"存在性"与"实质性"分开记账的：交付能力**不给** `falsifiable_check`（因为没内容可证伪），并且**不进** `CAPABILITY_VERDICT`（因为"未裁定"而非"已裁定通过"）。

### 4.3 DPH 侧的三处适配（与材料的差异）

| # | 材料做法 | DPH 适配 | 理由 |
|---|---|---|---|
| **A-1** | 交付能力**完全**不出现在裁定文件里（`[F-03]` 19 条） | **必须出现**，但 `verification_depth = EXISTENCE` + `disclaimer` | DPH 的 `requirement_coverage` 门要求"每个 `REQUIRED_OUTPUT` 由 ≥N 个到达 CRITICAL 的结果支付"（`delivery/requirement-coverage.ts`）。**交付能力若从 IR 里消失，该门会判"未覆盖"**——材料的"不出现"在 DPH 的 fail-closed 语义下是**阻塞** |
| **A-2** | `falsifiable_check` 为空 | `falsifiable_thresholds = []` **合法**（`judge=machine` 的 refine 要求"≥1 项"——**故交付能力必须显式声明其阈值对象为产物形态**） | 交付物形态**是**可机械断言的（sheet 名、行数、列数、数据类型、四位小数）。材料侧 `P1-C6` 的 `criterion` 就写满了这些（"1800 行 x 21 列，全部四位小数"）——**这些是阈值，只是没写进 `falsifiable_check` 字段**。DPH 侧应把它们**提取到阈值里**，而非留空 |
| **A-3** | 差额 4 条只出现在 `[F-04]` 总账 | 差额 4 条**同时**出现在 `CapabilitySpec` 与覆盖门输入中 | 使"存在性验证"成为**受门的、可见的**状态，而非靠"某文件里没有它"来表达 |

> **A-2 的推论**：材料侧的 4 条交付能力**实际是可机械化的**（形态断言），只是作者**没有把形态写成阈值**。DPH 侧应把它们提升为 `SUBSTANTIVE` + `machine_check=DELIVERY`，**而非** `EXISTENCE`。**`EXISTENCE` 只应留给"产物存在但无法校验内容"的情形**——而交付物的形态恰恰是可校验的。
>
> **故本支线的建议是**：`EXISTENCE` 深度的适用范围**比材料侧窄**。材料侧 4 条中有 4 条（全部）应归 `SUBSTANTIVE`（形态可验）；真正需要 `EXISTENCE` 的是**未在材料侧出现的情形**——例如"论文成稿存在"（`[F-24]` `main.docx` 3717829 B）这类**只有存在性可验**的产物。

### 4.4 因此：`EXISTENCE` 集合的实测判定

| 对象 | 深度 | 理由 |
|---|---|---|
| `result1..4.xlsx` | **SUBSTANTIVE** | 形态可验（sheet 名 / 行数 / 列数 / 四位小数 / 数据类型）——`[P-08][2]` 的 F3 major 正是**形态不一致**，且它**被抓到了**（证明形态检查有效） |
| 表 1–6（论文中的表） | **SUBSTANTIVE** | 抽样格与收敛解一致（`[P-08][0]` 的 F1 major 抓到第 4 位小数不一致） |
| 图（`figures/*.png`，24 个） | **EXISTENCE** | DPH 侧 `figure_data_consistency` 门校验 `data_hash`，但**图的美观/可读性无机械判据** |
| 论文成稿（`paper/main.docx`） | **EXISTENCE** | 只有 `contentExists(bodyText)`（`EMPTY_CONTENT_CHARS = 200`）这一条非空判据（`delivery/delivery-grade.ts`） |
| 代码（`code/*.py`，9 个） | **EXISTENCE** | `stale_detection` 的 S-007 字节校验可验**新鲜度**，不验**正确性** |

> **结论**：`EXISTENCE` 适用于**"存在性之外无机械判据"**的产物（图、成稿、代码文件本身）。**交付表格不属于此列**——它的形态是完全可机械校验的。**这是本支线与材料侧 `[F-04]` 账目的实质差异，须记录。**
