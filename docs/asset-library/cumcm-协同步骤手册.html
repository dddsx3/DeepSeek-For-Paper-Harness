Human-in-the-Loop · 协同模式

对话式协同模式 CUMCM 操作手册

把原来的 API 全自动流水线，拆成 5 个"人监督"的对话会话。每个会话：投什么 → 怎么要求（可复制 prompt）→ 产出什么 → 你在哪里喊停检查。

协同模式 vs 自动流水线（这决定"怎么要求"）

维度自动 API 流水线对话式协同（你正在切换）
触发技能按产物契约自动串门每个会话你用一个 prompt 让它加载对应 skill
检查点自动闸门（capability/覆盖率脚本）在 ③⑦⑩ 三处你喊停 → 审阅 → 放行
上下文分步清场，产物文件传递大文件不重投：给路径让模型 Read；每会话续接附一句"产物路径"
skill 加载由 Chairman/Loop 调用你在 prompt 里显式说："加载并执行 comp-modeling 技能"
纠错自动重试（浪费额度）你当场看，不满意就一句话让它改，不烧自动重试
开跑前一次性准备（跟对话无关）：① 把 skills/shared-scripts/ 物化为 _utils/ 并设置 $MH_TOOLS_DIR→到 tools/（否则各步 python 校验脚本找不到）；② docx 交付前先 npm install（在 tools/docx-cn-engine/）。③ 给赛题建工作目录：user_data/ 放赛题附件。
1

开题 + 建模（赛题分析 · 建模求解）

自动步骤 ①② 合为一会话 → comp-prob-analysis + comp-modeling

📥 投给窗口的文件

  • 赛题原文（PDF/图片/文本）放入 user_data/。⚠ 若赛题含图（地图/流程图），需要模型视觉读图。
  • 大表格/数据集不要全贴——放 user_data/，prompt 里让模型"按需 Read，用 offset/limit 读局部"。
  • 一句话告知：你是国赛，赛道题目编号、工作目录路径。

💬 Prompt（复制即用，把【】替换）

现在陪我做【2025C 题】国赛数模，工作目录 D:\modex\_assets_extracted\_cumcm\。

第一步：加载并执行 skills 库里的 comp-prob-analysis 技能。
- 赛题在 user_data/【赛题文件.pdf】，附件在 user_data/。
- 若附件较大，用 Read 带 offset/limit 读局部，不要整篇 cat。
- 产出 PROBLEM_ANALYSIS.md（拆子问题、定义变量、拟定建模思路）和 CAPABILITY_CHECKLIST.json。

做完后：只把这题的【子问题划分】和【每问大致方向】列给我，先停，我确认了建模方向你再往下，不要直接转 comp-modeling。

💬 放行后的 Prompt

方向 OK。第二步：加载并执行 comp-modeling 技能。
- 依据 PROBLEM_ANALYSIS.md 与 user_data/ 为每个子问题建立数学模型、推导公式、设计算法。
- 产出 MODELING_REPORT.md（≥1.5KB），并在结尾跑 python _utils/modeling_coverage_check.py --checklist CAPABILITY_CHECKLIST.json --modeling MODELING_REPORT.md，把每条能力是否有建模着落贴给我。
- 用 references/methods_table.md 选方法。
完成后停下，把【每问公式 + 求解思路】给我过目。

📦 产出物

  • PROBLEM_ANALYSIS.md · CAPABILITY_CHECKLIST.json · MODELING_REPORT.md

🧑💼 人工检查点（此处喊停）

  • ① 子问题划分是否贴题、有无漏问；② 每问方法选型是否合理（优化？回归？微分方程？）；③ 符号/假设是否自洽。不合格就一句"第 X 问方法不对，改成…"让它改，再放行。
2

求解（编程实现）

自动步骤 ③ → comp-code

📥 投给窗口的文件

  • 不用重投。只告知：MODELING_REPORT.md 在工作目录、user_data/ 有数据。让模型自己 Read。

💬 Prompt（复制即用）

第三步：加载并执行 comp-code 技能。
- 依据 WORKSPACE 下的 MODELING_REPORT.md，为每个子问题写独立 python 脚本 code/problemN.py。
- 长求解一定【前台同步等返回】（timeout 3600），禁止丢后台。
- 跑完跑 _utils/data_ingest_check.py、delivery_audit.py、leakage_audit.py、claim_code_check.py 这几个地基校验，有问题先修。
- 产出 figures/problem_*_results.json、figures/all_results.json 和 RESULTS.md（每问方法+数值结果）。

逐问给我汇报：【子问题N】方法的数值结果 + 一句合理性判断（量级对不对、是否收敛）。

📦 产出物

  • code/problem1.py…problemN.py · figures/problem_*_results.json · RESULTS.md

🧑💼 人工检查点（此处喊停）

  • 看数值是否合理：量级能否对上题目里的已知量/你的常识。让模型交代收敛性/可行性。对不上的要求"查一下第 X 题求解策略"。这是全场最关键的数据可信度检查。
3

制图（数据图 + 示意图）

自动步骤 ④⑤ → paper-figure + paper-figure-html（平替 drawio）

📥 挑图式投入

  • 你已经要在窗口里尽量让模型先出草图给你选，而不是一次性全量出。告知路径：figures/*_results.json、RESULTS.md。

💬 Prompt（先选图清单）

第四步：加载并执行 paper-figure 技能（数据类图）。
- 依据 figures/problem_*_results.json 与 RESULTS.md。
- 先读 _utils/figure_recipes_competition.md 选配方，按《图型/长宽比档位表》控制 figsize，数据线 lw≥0.9、刻度≥8pt。
- 先【只列图清单】：每问几张、图型是什么、一句话说明"这张图证明什么"。我勾选后再绘制。
- 每张图给我一句图注 + 关键结论；出图用 save_fig，收进 figures/fig_*.pdf，并登记 figures/latex_includes.tex。

💬 Prompt（再出示意图）

第五步：加载并执行 paper-figure-html 技能。
- 画【技术路线图 fig_roadmap】+【问题一求解流程图 fig_flow_q1】+【问题二流程 fig_flow_q2】（若有多问按需）。
- 用 electron printToPDF 转成矢量 PDF；跑 _utils/html_pdf_check.py 几何自检（文字重叠/越界）。
- 至少让我看到图标题+结构，我确认版式后再批量渲染。

📦 产出物

  • figures/fig_*.pdf（数据图）+ fig_{roadmap|flow_q1|flow_q2}.html/.pdf（示意图）+ latex_includes.tex

🧑💼 人工检查点（此处喊停）

  • 肉眼验图：数据图有没有坐标/单位/图例、线清不清、色板可读；示意图有没有文字重叠/越界。
👁 依赖模型能力提醒：本步视觉自检脚本（data_fig_vision_check.py / drawio_vision_check.py）只有 .pyc 无源码，会自动降级——所以这步必须靠你肉眼把关，别指望脚本。
4

复核 + 写正文（对抗复核 · 论文撰写）

自动步骤 ⑥⑦ → comp-review + comp-paper-zh-docx（🚩大检查点）

📥 投给窗口的文件

  • 只在必要时投 PROBLEM_ANALYSIS.md/MODELING_REPORT.md/RESULTS.md 的路径；大正文分段让模型读不整贴。

💬 Prompt（先复核）

第六步：加载 comp-review，对前三步产物（PROBLEM_ANALYSIS / MODELING_REPORT / RESULTS）做独立逻辑对抗复核，重点找：方向反、重复计量、外推过硬、漏变量、跨问矛盾。
产出 REVIEW.md，并【逐条列出你挑到的硬错 + 证据】。我确认没有会翻车的硬错，才允许你写正文。

💬 Prompt（再审阅后放行写正文）

第七步：加载 comp-paper-zh-docx，按国赛（cumcm）章节结构写中文论文：
摘要~1页、问题重述、模型假设、符号说明、每问一节的建模与求解、灵敏度分析与检验、模型评价与推广、参考文献、附录代码。
- 插图用 Markdown 语法 ![图N：标题](figures/xxx.png)（确保文件真实存在）；正文页数≥20（docx 模式按字符折算）。
- 产出单文件 paper/main.md（≥5KB，UTF-8）；结束自检不得残留 LaTeX 命令（\begin\includegraphics\cite 等）。
写完后给我：章节清单 + 每章要点，我先通读再审。

📦 产出物

  • REVIEW.md · paper/main.md

🧑💼 人工检查点（🚩 全文最关键，此步必停）

  • 通读 paper/main.md：逻辑闭环、数值与 RESULTS.md 一致、图表是否都是论据、有没有套话占位（"如图所示…"这种换哪张图都成立的）。
  • 逐章看完，把要改的章节点名"第 X 节结论反了/缺灵敏度，改"。此处没把住，后面都是白费力。
5

打磨 + 格式 + 导出 Word

自动步骤 ⑧⑨⑩ → format-profile + docx-format-check + docx-cn-engine

📥 投给窗口的文件

  • 国赛官方格式说明（PDF/截图/文字）——让 format-profile 解析成样式档案。

💬 Prompt（改进 + 格式 + 导出）

【改进，注意：库里的 auto-paper-improvement-loop 技能缺失，改用人工反馈驱动】：
我把 review 出的问题和我要改的地方列给你（【贴你的修改要求】），你据此迭代改写 paper/main.md，每轮给我 diff 摘要，我点头再下一轮。

【格式】加载 format-profile：解析我贴的国赛格式，参照 docx_style_profiles/competition_zh.json 与 covers/cumcm.json，产出 styles/rules_profile.json。

【导出】加载 docx-format-check 对 paper/main.md 自检修复（代码块/公式编号/表格/图片/Markdown残留），然后运行：
    node tools/docx-cn-engine/md_to_docx.js  →  paper/main.docx（国赛封面+样式）
给我最终 docx 的保存路径。

📦 产出物

  • paper/main.md（打磨后）· styles/rules_profile.json · paper/main.docx 🎯

🧑💼 人工检查点

  • 打开 main.docx 视觉核对：封面（cumcm.json）、字体字号、图表编号、无 Markdown 残留。
🟥 缺内容提醒：本步 ①改进循环无内置技能——用"你贴修改要求 → 它改 → 你点头"代替；②docx 模板深查（docx_template_analyze/fill.py）只有 .pyc 会降级，最终格式以你亲眼核对 docx 为准；③导出前先在 tools/docx-cn-engine/ 跑 npm install。
协同模式要点：① 每会话一个 prompt 显式"加载并执行 XX 技能"；② 三处硬检查点（S2 数据可信、S4 全文审阅、S5 成品 docx）必须你亲自把关；③ 大文件一律给路径不放正文，省窗口预算；④ 新开窗口续接时首句写"上一步产物在 X 路径，可用 Read 读取"。 图例：📥输入 · 💬prompt · 📦产出 · 🧑💼检查点 · 👁依赖模型能力 · 🟥缺内容。生成 2026-09-10。
