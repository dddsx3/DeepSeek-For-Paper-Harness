# 理想交付形态规格（对齐优秀论文用）

> `apps/paper-shell/src/cli.ts`（交付写入段）、`delivery/*`（门禁）、`scripts/export-pdf.py`（模板导出）。

## 一、交付包（一次运行产出的文件）

| 文件 | 内容 | 谁生成 | 门槛 |
|---|---|---|---|
| `report.md` | 论文主稿（12 章骨架 + 机器数字回读 + 执行输出附录） | 渲染器（harness） | ≥ 4,000 字节 |
| `paper.pdf` | **PDF 交付**：数字资产 CUMCM 模板（`cumcmthesis.cls`）+ xelatex，16 页量级 | `scripts/export-pdf.py` | ≥ 50,000 字节；**模板缺失即拒绝导出** |
| `paper.docx` | Word 交付（A4 / 25mm 边距 / 宋体小四 / 1.5 倍行距 / 黑体标题 / 图 300dpi PNG） | `scripts/export-docx.py` | ≥ 5,000 字节；**docx 预检 0 致命才写出** |
| `run-report.json` | 运行报告：`delivery_path` / `grade` / `tier` / `code_run_timeout_ms` / `data_files`(sha256+bytes) / `figures` / `figure_links_broken` / `usage` / `attachments` | CLI | ≥ 200 字节 |
| `audit-trail.json` | **完整审计轨迹**：每个事件的 seq / ts / eventType / actor / detail | CLI | — |
| `artifact-bodies.json` | **模型原文留痕**：E1 分析全文、容器文本（已凭据脱敏） | CLI | — |
| `data/<basename>.json` | **执行输出**：代码真跑出来的原始字节（论文每个数字的来源） | 执行链 → 落盘 | 每份记录 sha256 |
| `figures/<id>.svg` + `.png` | 图：harness 从 IR 渲染的 SVG，及导出用 PNG | 图生产者 | 与正文引用一致，断链记入 run-report |
| `figure-manifest.json` | 图清单（每图 sha256 + 渲染器版本） | CLI | 有图时产出 |
| `docx-precheck-report.md` | docx 预检 16 类逐条结果 | 预检 | 0 致命才允许导出 |
| `deliverable.zip` | 上述（含二进制 PDF/docx）的确定性 zip | CLI | 同 cassette 重跑同 sha256 |
| `sha256.txt` | `report.md` 的 sha256 | CLI | — |

**证据链完整性**：论文里的每个数字 → `report.md` 结果表 → `data/*.json` 原始字节 → `RunArtifact`/`ExecutionRecord`（审计轨迹）→ 代码文本（`artifact-bodies.json`）。这条链是**机械闭合**的。

## 二、论文内容（12 章，逐章说明谁写、写什么、门槛）

| # | 章 | 内容来源 | 门槛（机械可判） |
|---|---|---|---|
| 1 | **摘要** | harness 合成：标题 + 关键结论（每个数字必须是 Result 值/不确定度） | 守卫拒时改中性兜底摘要（不写引擎报错） |
| 2 | **问题重述** | 题面（harness 注册的 RequirementSpec，**不含内部提示词**）+ 模型自写重述 | 要素：自己的话，≥200 字 |
| 3 | **问题分析** | **E1 分析逐问切段**（每问一段：方法族 + 为什么 + 难点）+ 模型补充 | 逐问覆盖 `R-Q1…R-Qn`；≥600 字 |
| 4 | **模型假设** | IR 的 `AssumptionSpec` 表（假设 / 来源 / 风险 / 可检验） | 每条被 ModelSpec 引用 + 有 justification_refs |
| 5 | **符号说明** | IR 的 `SymbolSpec` 表（符号 / 含义 / 单位） | 符号须被模型引用 |
| 6 | **模型建立与求解** | **IR 渲染**：方程表（id / 表达式 / 类型 / 单位）+ 模型表（id / 目标 / 约束 / 引用）；模型 `methods` 散文接在其下 | 至少一条方程或模型；散文补足 |
| 7 | **结果对比与校核** | IR 注入结果表（量名 / 数值 / 单位 / 不确定度 / 来源 Result id）+ 结论（逐字核对）+ 校核声明 | 结论里每个量必须逐字出现（或 `{R-id}` 由 harness 注入）；数字只能来自 Result |
| 8 | **模型评价与推广** | 模型自写 | 四要素：优点 / 局限 / 敏感性 / 推广；≥500 字 |
| 9 | **AI 声明** | harness 固定文本（说明数字由 IR 渲染、文字由模型生成、实质正确性不在 harness 判定范围） | — |
| 10 | **参考文献** | 模型自写 | ≥3 条完整条目，且至少一条与所用方法相关 |
| 11 | **数据附录** | harness：执行输出文件清单 | 与 `data/` 实际文件一致 |
| 12 | **代码附录** | 模型导语 + **harness 渲染的真实代码** | 点名实现了哪几问；≥200 字 |

**另附**：`## 附录：交付标注（自动生成）`——MARKED 等级下逐条列出未通过项（critical gate / 评审缺陷 / V1–V4 结构校验 / 空白章节 / 退化产出），读者一眼看到哪些地方需要复核。

## 三、三条交付路径（`delivery_path`，决定论文形态）

| 路径 | 含义 | 论文形态 |
|---|---|---|
| `A-produce-chain` | 代码真跑、数字经 jsonPath 回读、铸出 Result/Claim | **最强**：结果表数字来自真实执行 |
| `A-normalized-no-code` | 容器合法但无代码 | 结构齐备，无执行数字 |
| `B-e1-direct` | 容器多次被拒后的兜底：E1 分析直接渲染进骨架 | 保留分析价值，但**未经规范 IR 验证**（标注说明） |

## 四、链上门禁（产出前教学 + 产出后核验，两段都在）

**产出前**（写在提示里，模型第一次发射就该满足）：PAPER CONTRACT 十一行（八键 / 逐问归因 ≥600 / 四要素 ≥500 / 文献 ≥3 / 代码附录 ≥200 / 重述 ≥200 / 无空白 / 至少一图 / 每问自己的 Result+CRITICAL claim / 假设被引用且带 justification）、E1 STRUCTURE 三条（逐问锚点 `[[REQUIREMENT: R-Qn]]`、`e1_span` 逐字或 `#<n>` 序号引用、锚点同一性）。

**产出后核验**（不满足即拒，带针对性纠错与重试预算）：容器形状/首行版本标记、逐问覆盖、假设结构、图必填、散文要素、实质地板、空白密度、数字闭环（结论数字必须回到 IR）、算式自洽、E1↔E2 双向保真。

**交付前**：docx 预检 16 类（骨架齐备 / 无占位 / 表列对齐 / 公式定界符 / 引用可解析 / 字数 / 图片引用可解析 …），0 致命才允许导出。

## 五、当前**不具备**的（与参照物的差距，供你判断对齐方向）

1. **章节深度**：参照物问题分析 1,939 字、模型章 5,875 字（7 小节）、四问各 2.9–9.6K、附录 A–D 各 1–1.8K；当前地板是"要素齐备 + ≥600/500 字"，**远低于**参照物的论述密度。
2. **每问独立成章**：参照物是「6 问题一：…」「7 问题一模型的独立校核」「8 问题二：…」——**每问一章 + 独立校核章**；当前是单一「模型建立与求解」章 + 一张结果表。
3. **无 TOC / 无公式编号 / 无图表编号体系**；公式以文本形式在方程表里，不是 LaTeX 排版公式。
4. **参考文献 3 条量级**（参照物 3,914 字符），且只做"与方法相关"的弱校验，不做真实性核验。
5. **无探针/不变量闸**（C-3）、**无交付形态断言**（C-4，表头/列类型）、**无能力判定闸**（C-2）——这三条是审计里规划但未实现的**新闸门**。
6. **数值精度**：已做显示层归一（`2.2` 而非 `2.200000000000001`），但仍是文本数字，不是"声明即契约"的 rounded 表示。

## 六、对齐建议（若目标是参照物水准）

按收益排序，三条最有效：
1. **每问独立成章 + 独立校核章**：骨架从 12 章扩到"每问一章"，模型必须逐问给模型/求解/结果/校核——这是参照物形态的核心，也直接抬升论述密度。
2. **抬地板**：把每章下限从"要素齐备"提到参照物的量级（分析 ≥1,500 字且逐问 ≥300；模型章 ≥2,000；评价 ≥800）。
3. **公式与图表编号体系**：方程/图/表进 LaTeX 编号（PDF 里可交叉引用），使 PDF 从"能读"到"可评阅"。
