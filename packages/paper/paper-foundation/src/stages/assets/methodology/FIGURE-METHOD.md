# 作图方法论（题型无关）—— 从参考实现提炼

> 这份文档的作用是**固化"怎么做图"这件事本身**，使它不依赖具体题目。
> 参考实现（反编译 + 运行时捕获得到的原始资产）里，方法论的载体是：
> `figure_style_guide.md`（风格与决策表）、`figure_recipes_*.md`（109 个代码配方）、
> `paper-figure/SKILL.md`（十步工作流）、`error-prevention-by-problem-type.md`（按题型索引的防错手册）、
> `figure-distribution-exemplars.md`（好论文的图表分布范例）、以及 `figure_check.sh` /
> `recipe_audit.py` / `fig_include_size.py`（机械门禁）。这些都已原样迁入 `assets/`。
>
> 本文只做一件事：**把它们之间那条不变的骨架说清楚**，以便换一道题时照同一骨架走。

---

## 一、不变骨架（换任何题目都走这七步）

| # | 步骤 | 输入 | 产出 | 谁做 |
|---|---|---|---|---|
| 1 | **规划图集** | 题面 + 阶段 1 的 `FIGURE_MANIFEST` | `FIGURE_PLAN.json`：每张图讲什么、什么图型、照哪个配方、数据来自账本哪些 id | 模型 |
| 2 | **取配方** | 规划里的 `recipe: {category, number}` | 该配方的**完整正文**（骨架 + 要点 + 坑位） | harness 内联（模型读不到磁盘） |
| 3 | **写脚本** | 简报 + 规划条目 + 配方正文 | `figures/gen_fig_<id>.py`，一图一脚本 | 模型 |
| 4 | **机械门禁** | 脚本 | CRITICAL 违规清单 | `figure_script_quality`（照搬 `figure_check.sh`） |
| 5 | **溯源门禁** | 脚本 + 铸出的账本 | "每个数都能回账本" | `figure_script_traced` |
| 6 | **执行** | 脚本 + `_utils/plot_utils.py` + `results.json` | `figures/fig_<id>.png` | harness（确定性） |
| 7 | **对账 + 质检** | 产物 + 规划 | 齐备性 / 尺寸档位 / 风格 / 视觉硬伤 | `figure_manifest_reconcile`、`figure_size_buckets`、`figure_style_rules`、视觉质检 |

**七步里没有一步与题目有关。** 与题目有关的只有两样东西：① 第 1 步读的那份 `FIGURE_MANIFEST`
（由阶段 1 从题面产出）；② 账本里有哪些数（由阶段 3/4 真跑代码产出）。
**换题目 = 换这两个输入，骨架不动。**

## 二、题型无关 vs. 题型相关（这条界线是稳定迁移的前提）

| | 题型无关（本 harness 固化） | 题型相关（每道题各自产出） |
|---|---|---|
| 图型选择 | 决策表：数据形态 → 推荐图型 → 明确避免什么 | 本题的数据形态是什么 |
| 视觉规范 | 配色/字号/线宽/边框/图内文字三层闸/figsize 档位 | — |
| 代码起点 | 109 个配方 + 范本 | 选哪一条配方 |
| 流程 | 规划→取配方→写脚本→门禁→执行→质检 | 图集清单（几张、各讲什么） |
| 质量红线 | 残图红线、判据线、置信带、防遮挡、多样性 | 本题的阈值/约束线画在哪 |
| 数字来源 | "必须从铸出的账本读，不得硬编码" | 账本里有哪些 result_id |

**推论**：稳定性来自"题型相关的那一列足够窄"——只有清单与账本。任何把题目细节写进
规范/门禁的做法，都会破坏迁移性。**本仓库的门禁与简报里不允许出现具体题目的名词。**

## 三、参考实现里那四条"稳定性硬规则"（我最初漏掉的）

这四条不是风格偏好，是参考在多次实战后写下的，且**每条都影响跨题稳定性**：

1. **图 >5 张时先建 `figures/_figbase.py` 共用引导模块**
   > *"实测这是高分图集的共同做法：把样板收敛到一处，几十份脚本不再各写各的，也避免各图指标口径不一致导致论文数字打架。"*

   缺了它，每份脚本各自重造口径函数——**同一篇里两张图的同一个量可能算法不同**。
   这与题型无关，纯粹是"多图篇"的工程纪律。

2. **多面板合成在单个图内实现**（`[2-panel]` / `[4-panel]`，panel ≤ 4）
   > *"multi-panel 在**单个 PDF 内**实现（不是写两张 PDF）"*、*"panel 数量 ≤ 4"*。

   参考的成图基本都是 2–4 panel 的合成（`(a)` 场分布 + `(b)` 剖面）。**"出版级"的观感主要来自这一层**，
   而它是纯排版决策——与题目无关。

3. **图内文字三层闸，但"不要过度收缩"**
   > *"本条减的是'文字'，不是'信息'和'图表能力'。该有的多 panel、置信带、判据线、丰富图型一个都不能少。"*

   只抄"最小化"、不抄"不要过度收缩"，会把 ★极值标注、判据线、数值框这些**信息性元素**一起压掉。

4. **脚本必须从真实数据源读、不得硬编码**（`Key Rules`），并由 `facts_audit --stage figure` 审。
   本仓库具体化为"从铸出的 `results.json` 读"，落在 `figure_script_traced`。

## 四、`fig_include_size.py` 的尺寸闭环（题型无关，且极易踩坑）

`r = 高/宽` → 该写的**原生** figsize 宽：

| r | 上页显示宽 | 原生宽 | 例子 |
|---|---|---|---|
| ≤ 0.80 横图 | 5.53in | **6.0in** | `(6.0, 3.8)`；1×2 横排 `(6.0, 2.8)` |
| ≤ 1.20 近方 | 4.55in | **5.0in** | 2×2 多面板 `(5.0, 4.9)`；等比例几何图 `(5.0, 4.8)` |
| ≤ 1.60 偏竖 | 3.25in | **3.6in** | `(3.6, 5.0)` |
| > 1.60 瘦高 | 2.73in | **3.0in** | `(3.0, 5.4)` |

- 目标**缩放比 0.9–1.1**（`k = 上页显示宽 ÷ 原生宽`）；矢量图略放大（1.0–1.6）无害。
- 高度上限 **8in**。门禁 `figure_size_buckets` 容差 **15%**。
- ⛔ 最易踩：**2×2 与等比例几何图都是"近方图"，只能给 5.0in**。写 7.2in 看着"没超 7.5"，
  实际缩到 0.63 → 刻度 8.5pt 变 5.4pt。
- ⛔ 需要更多信息量时**加 panel 密度，不要摊大画布**。

## 五、两条"防塌方"判据（参考的原话，值得逐字记住）

1. **图型与规划对账**（`recipe_audit.py` 的用途）
   > *"图表质量塌方的首要原因不是'不知道该画什么'，而是规划里写对了图型、执行时却凭印象退化成 plot/bar/scatter。"*

   → 落成 `figure_type_match`。**判不出来一律放行**（参考口径"宁漏不误"）——
   把真图画法判成退化，比漏判更糟。

2. **过小的产物 = 疑似损坏**
   > FINAL GATE：*"PDF < 5000 bytes → FAIL（likely broken）"*

   → 落成 `figure_completeness` 的产物尺寸下限（PNG 取 3000 字节）。

## 六、跨题迁移的验收方式（怎么知道"真的能迁移"）

不看某一题的图好不好看，看**四条与题无关的判据**：

1. **骨架未变**：换题后第 1–7 步一步不少（尤其第 2 步"取配方"与第 7 步"视觉质检"）。
2. **规范里没有题目名词**：简报/门禁里出现具体题目词汇 = 迁移性已破。
3. **图集由阶段 1 驱动**：换题只改 `FIGURE_MANIFEST`，不改规范。
4. **门禁的误报率**：同一套门禁在第二道题上仍然"只拦真问题"——门禁若依赖题目特征，第二道题必然大面积误报。

**这四条是本 harness 的自检清单**；它们能过，才谈得上"稳定迁移"。
